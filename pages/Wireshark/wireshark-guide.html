// 01 — Introduction

Apa itu Wireshark?

Network protocol analyzer paling populer di dunia — gratis, open-source, dan digunakan oleh jutaan profesional IT.

📡 Definisi

Wireshark adalah network protocol analyzer — tools yang memungkinkan kamu menangkap (capture) dan menganalisis lalu lintas jaringan secara real-time. Bayangkan Wireshark seperti "X-ray untuk jaringan komputer" — kamu bisa melihat setiap packet data yang lewat di kabel atau WiFi, lengkap dengan detail protokol, isi data, dan timing-nya.


Nama "Wireshark" sendiri berasal dari kata wire (kabel/jaringan) + shark (hiu = pemburu handal). Dibuat oleh Gerald Combs tahun 1998, awalnya bernama Ethereal sebelum berubah nama ke Wireshark di 2006.

🎯 Fungsi Utama
  • Capture live network traffic
  • Analisis protocol (TCP, HTTP, DNS, dll)
  • Troubleshoot masalah jaringan
  • Security incident investigation
  • Malware traffic analysis
  • Belajar cara kerja protokol jaringan
  • Forensik digital dan bukti jaringan

Kapan Menggunakan Wireshark?

🔧
Network Troubleshooting
Website lambat? Koneksi putus-putus? Wireshark bisa menunjukkan persis dimana bottleneck terjadi — apakah retransmission, high latency, atau packet loss.
🛡️
Security Analysis
Deteksi port scan, brute force, beaconing malware, C2 communication, dan berbagai anomali traffic yang mengindikasikan serangan siber.
📚
Learning & Research
Cara terbaik memahami cara kerja protokol jaringan adalah melihat packet aslinya. Wireshark adalah lab interaktif terbaik untuk belajar networking.

Kelebihan & Kekurangan

✅ Kelebihan
  • Free dan open-source (GPL)
  • Cross-platform: Windows, Linux, macOS
  • Support ribuan protokol (1000+)
  • GUI yang powerful dan intuitif
  • Filter syntax yang fleksibel
  • Export ke berbagai format
  • Community dan dokumentasi besar
⚠️ Kekurangan & Limitasi
  • Tidak bisa decrypt HTTPS tanpa private key
  • Butuh privilege admin/root untuk capture
  • High-volume traffic bisa membebani RAM
  • Tidak real-time alerting (bukan IDS)
  • Bisa disalahgunakan untuk sniffing ilegal
⚖️
LEGAL & ETHICAL WARNING
Menggunakan Wireshark untuk menangkap lalu lintas jaringan yang bukan milikmu atau tanpa izin adalah ILEGAL di hampir semua yurisdiksi. Ini termasuk sniffing WiFi publik untuk mencuri kredensial, menangkap traffic di kantor tanpa otorisasi, atau penggunaan dalam kegiatan kriminal siber. Selalu gunakan Wireshark di lingkungan lab sendiri, dengan izin eksplisit, atau dalam konteks legal seperti CTF, pen-testing yang diizinkan, atau jaringan pribadi sendiri.

Instalasi Wireshark

Panduan instalasi lengkap untuk tiga platform utama beserta troubleshooting error umum.

Sistem Requirements

Win 10/11
🧠
RAM
Min 4GB
💾

⚙️
CPU
64-bit

Langkah Instalasi

1
Download installer dari website resmi: https://www.wireshark.org/download.html — pilih versi Windows x64 Installer.
2
Jalankan installer sebagai Administrator. Klik "Next" untuk memulai.
3
Penting: Pastikan centang "Install Npcap" — ini adalah driver wajib untuk packet capture di Windows. Tanpa Npcap, Wireshark tidak bisa menangkap traffic.
4
Pada dialog Npcap, centang "Install Npcap in WinPcap API-compatible Mode" untuk kompatibilitas dengan tools lain.
5
Selesaikan instalasi dan restart komputer jika diminta. Wireshark siap digunakan.
💡
Npcap adalah library packet capture untuk Windows, pengganti WinPcap yang sudah tidak di-maintain. Npcap jauh lebih modern, mendukung Windows 10/11, dan bisa berjalan dalam mode loopback untuk menangkap traffic localhost.

Common Installation Errors

Biasanya karena Npcap tidak terinstall dengan benar. Solusi: uninstall Npcap dari Control Panel → install ulang dari https://npcap.com/#download. Jika masih error, jalankan Wireshark as Administrator.
Tidak semua WiFi driver mendukung promiscuous mode. Solusi: gunakan USB WiFi adapter yang kompatibel (misalnya Alfa AWUS036ACH), atau gunakan wired Ethernet adapter untuk capture yang lebih reliable.
Jalankan Wireshark sebagai Administrator (klik kanan → Run as administrator). Di Windows 10/11, packet capture membutuhkan privilege elevated.

Ubuntu / Debian

terminal — bash
# Update package list
$ sudo apt update

# Install Wireshark
$ sudo apt install wireshark -y

# Saat prompt "Should non-superusers be able to capture packets?" pilih YES

# Tambahkan user ke grup wireshark (agar tidak perlu sudo)
$ sudo usermod -aG wireshark $USER

# Logout lalu login kembali, atau jalankan:
$ newgrp wireshark

# Verifikasi instalasi
$ wireshark --version
Wireshark 4.2.x (Git v4.2.x)

Fedora / RHEL / CentOS

terminal — bash
$ sudo dnf install wireshark wireshark-qt -y
$ sudo usermod -aG wireshark $USER
$ sudo setcap cap_net_raw,cap_net_admin+eip /usr/bin/dumpcap

tshark (CLI Version)

tshark — CLI capture
# Install tshark saja (tanpa GUI)
$ sudo apt install tshark -y

# List interface tersedia
$ tshark -D

Di Linux, Wireshark menggunakan libpcap (bukan Npcap) untuk packet capture. Pastikan setcap sudah dikonfigurasi dengan benar agar tidak perlu sudo setiap kali.

Panel teratas yang menampilkan daftar semua packet. Setiap baris adalah satu packet dengan kolom: nomor urut, timestamp, source IP, destination IP, protokol, dan ringkasan info. Warna berbeda menandakan protokol berbeda.

Panel bawah menampilkan raw bytes dalam format hexadecimal (kiri) dan ASCII yang dapat dibaca (kanan). Field yang dipilih di Details pane akan ter-highlight di sini.

Input field untuk Display Filter — memfilter packet yang DITAMPILKAN (bukan yang di-capture). Mendukung syntax Wireshark yang sangat powerful. Tombol bookmark menyimpan filter favorit.
📊 Status Bar
Bar di paling bawah menampilkan informasi capture: jumlah packet total, yang sedang ditampilkan, expert info alerts, dan profile yang aktif.
// 04 — Capture

Packet Capture

Cara memulai, menghentikan, dan mengelola sesi packet capture dengan efektif.

Memulai Capture

1
Buka Wireshark → akan tampil daftar network interface yang tersedia dengan grafik traffic real-time.
2
Pilih interface yang ingin di-capture. eth0/Ethernet untuk kabel, wlan0/Wi-Fi untuk wireless.
3
Double-click interface atau tekan tombol ▶ (Start) di toolbar — capture langsung dimulai.
4
Untuk menghentikan: tekan ■ (Stop) atau keyboard shortcut Ctrl+E.
5
Simpan hasil: File → Save As dalam format .pcap atau .pcapng.

Capture Options

Capture Filter
Filter yang diterapkan SEBELUM capture — mengurangi packet yang di-simpan. Berbeda syntax dari Display Filter!
tcp port 80 # hanya HTTP
host 192.168.1.1 # satu host saja
net 192.168.1.0/24 # subnet tertentu
not port 443 # exclude HTTPS
Ring Buffer
Untuk long-term capture, aktifkan ring buffer di Capture Options: simpan ke file terpisah setiap X MB atau X menit. Mencegah single file yang terlalu besar.
Promiscuous Mode
Mode default yang menangkap semua packet di network — bukan hanya yang ditujukan ke komputer kamu. Sangat penting untuk analisis jaringan yang komprehensif.
⚠️
Capture di Jaringan Sibuk: Pada jaringan dengan traffic tinggi (data center, enterprise), sesi capture yang lama dapat menghasilkan file PCAP berukuran gigabyte. Gunakan capture filter untuk membatasi data, aktifkan ring buffer, dan pastikan disk storage mencukupi.

Format File

.pcap
Format klasik, kompatibilitas luas dengan semua tools. Mendukung satu data link type per file. Tidak mendukung komentar atau metadata tambahan.
.pcapng (Rekomendasi)
Format modern, next-generation. Mendukung multiple interfaces, komentar per-packet, statistik tambahan, dan metadata lebih lengkap. Default format Wireshark terbaru.
.cap / .etl
Format proprietary dari tools lain (Cisco, Microsoft). Wireshark bisa membuka banyak format ini via File → Open.

Display Filter Guide

Referensi lengkap filter Wireshark — cari, copy, dan terapkan langsung ke analisis kamu.

IP / Network
ip.addr == 192.168.1.1📋 copy
Filter berdasarkan IP address (source atau destination).
Contoh: ip.addr == 10.0.0.5 | ip.src == 172.16.0.0/16
🎯 Kasus: Isolasi traffic dari/ke IP spesifik yang mencurigakan.
IP / Network
ip.src == 192.168.1.105📋 copy
Filter hanya packet dengan source IP tertentu.
Contoh: ip.src == 192.168.1.0/24
🎯 Kasus: Lihat semua traffic yang KELUAR dari host tertentu.
IP / Network
ip.dst == 8.8.8.8📋 copy
Filter packet yang menuju destination IP tertentu.
Contoh: ip.dst == 8.8.8.8 (traffic ke Google DNS)
🎯 Kasus: Monitor traffic yang masuk ke server tertentu.
TCP
tcp.port == 443📋 copy
Filter packet TCP pada port tertentu (source atau destination).
Contoh: tcp.port == 80 | tcp.port == 22 | tcp.port == 3306
🎯 Kasus: Analisis traffic HTTP, SSH, MySQL berdasarkan port.
TCP Flags
tcp.flags.syn == 1📋 copy
Filter packet dengan flag SYN aktif — awal koneksi TCP.
Contoh: tcp.flags.syn == 1 and tcp.flags.ack == 0
🎯 Kasus: Deteksi SYN flood / port scan — banyak SYN tanpa ACK.
TCP Flags
tcp.flags.reset == 1📋 copy
Filter packet dengan RST flag — koneksi di-reset paksa.
Contoh: tcp.flags.reset == 1 and ip.src == 10.0.0.5
🎯 Kasus: Deteksi port scan (RST dari port tertutup), koneksi bermasalah.
TCP
tcp.stream eq 5📋 copy
Filter berdasarkan nomor stream TCP — isolasi satu session.
Contoh: tcp.stream eq 0 (stream pertama)
🎯 Kasus: Rekonstruksi satu sesi HTTP/FTP dari banyak packet.
TCP
tcp.analysis.retransmission📋 copy
Tampilkan hanya packet yang merupakan retransmission.
Contoh: tcp.analysis.retransmission or tcp.analysis.lost_segment
🎯 Kasus: Diagnose packet loss, network congestion, connection issues.
UDP
udp.port == 53📋 copy
Filter packet UDP pada port tertentu.
Contoh: udp.port == 53 (DNS) | udp.port == 67 (DHCP)
🎯 Kasus: Analisis DNS, DHCP, SNMP, VoIP (SIP/RTP).
HTTP
http📋 copy
Tampilkan semua traffic HTTP (port 80, non-encrypted).
Contoh: http.request.method == "GET"
🎯 Kasus: Analisis web traffic, credential sniffing pada HTTP.
HTTP
http.request.method == "POST"📋 copy
Filter HTTP POST request — biasanya berisi form data, login, upload.
Contoh: http.request.method == "POST" and http contains "password"
🎯 Kasus: Deteksi credential submission via form login HTTP.
HTTP
http.response.code == 200📋 copy
Filter berdasarkan HTTP status code response.
Contoh: http.response.code == 404 | http.response.code >= 500
🎯 Kasus: Troubleshoot error 404 (not found), 500 (server error).
DNS
dns📋 copy
Tampilkan semua traffic DNS (query dan response).
Contoh: dns.flags.response == 0 (hanya query)
🎯 Kasus: Analisis resolusi domain, DNS tunneling, suspicious domains.
DNS
dns.qry.name == "evil.com"📋 copy
Filter DNS query untuk domain name tertentu.
Contoh: dns.qry.name contains "malware" | dns.qry.name contains ".ru"
🎯 Kasus: Deteksi resolusi domain C2, phishing, malware.
TLS/SSL
tls📋 copy
Tampilkan semua traffic TLS/SSL (HTTPS, SMTPS, dll).
Contoh: tls.handshake.type == 1 (Client Hello)
🎯 Kasus: Analisis TLS handshake, versi TLS yang digunakan.
TLS/SSL
tls.handshake.extensions_server_name📋 copy
Filter berdasarkan SNI (Server Name Indication) dalam TLS handshake.
Contoh: tls.handshake.extensions_server_name contains "google"
🎯 Kasus: Lihat domain tujuan dari koneksi HTTPS meskipun terencrypt.
ARP
arp📋 copy
Tampilkan semua packet ARP (Address Resolution Protocol).
Contoh: arp.opcode == 1 (ARP request) | arp.opcode == 2 (ARP reply)
🎯 Kasus: Deteksi ARP spoofing / poisoning (MITM attack).
ICMP
icmp📋 copy
Tampilkan semua packet ICMP (ping, traceroute, unreachable).
Contoh: icmp.type == 8 (Echo Request / ping)
🎯 Kasus: Analisis ICMP tunneling, ping flood, network reachability.
Payload Search
frame contains "password"📋 copy
Cari string tertentu dalam semua bytes packet (case-sensitive).
Contoh: frame contains "cmd.exe" | frame contains "SELECT"
🎯 Kasus: Cari credential, SQL injection, command execution dalam traffic.
Logic Operators
ip.addr == 1.1.1.1 and tcp📋 copy
Kombinasikan filter dengan AND, OR, NOT (atau &&, ||, !).
Contoh: http or dns | not arp | tcp and not tcp.port == 443
🎯 Kasus: Buat filter kompleks untuk menyaring traffic spesifik.

Memahami three-way handshake, TCP flags, dan cara menganalisis koneksi TCP di Wireshark.

TCP Flags Reference

SYN — Synchronize
Flag untuk memulai koneksi TCP. SYN=1, ACK=0 berarti ini adalah permintaan koneksi pertama dari client. Filter: tcp.flags.syn==1 && tcp.flags.ack==0
ACK — Acknowledge
Konfirmasi penerimaan data. Hampir semua packet TCP setelah handshake memiliki ACK=1. Filter: tcp.flags.ack==1
FIN — Finish
Mengakhiri koneksi TCP secara graceful. Proses 4-way: FIN→ACK→FIN→ACK. Filter: tcp.flags.fin==1
RST — Reset
Mengakhiri koneksi secara paksa dan abrupt. Sering muncul pada port scan (port tertutup) atau error. Filter: tcp.flags.reset==1
PSH — Push
Instruksi ke receiver untuk segera memproses data ke aplikasi tanpa menunggu buffer penuh. Filter: tcp.flags.push==1
URG — Urgent
Menandakan data urgent yang harus diproses lebih dahulu. Jarang digunakan dalam praktik modern. Filter: tcp.flags.urg==1

TCP Troubleshooting Cases

Retransmission terjadi ketika sender tidak menerima ACK dalam waktu yang ditentukan (RTO - Retransmission Timeout). Artinya packet sebelumnya kemungkinan hilang (packet loss). Penyebab: network congestion, kabel bermasalah, WiFi interference. Filter untuk cek: tcp.analysis.retransmission. Jika retransmission >1% dari total TCP packets, ada masalah serius di jaringan.
TCP Window Size mengontrol berapa banyak data yang bisa di-send sebelum menunggu ACK. Window Full berarti sender terkirim data sebesar window size tapi belum dapat ACK — harus tunggu. Zero Window berarti receiver memberi tahu sender untuk berhenti kirim (buffer penuh). Ini sering jadi bottleneck. Filter: tcp.analysis.window_full or tcp.analysis.zero_window
Banyak RST dari satu source IP ke berbagai port dalam waktu singkat = tanda kuat port scan (nmap, masscan). RST yang di-generate server berarti port tersebut tertutup. Cek dengan: tcp.flags.reset==1 and tcp.flags.ack==1 diikuti filtering per IP untuk melihat apakah ada pola scan. RST juga bisa muncul pada connection timeout atau firewall yang aktif drop connection.
Right-click packet TCP mana saja → Follow → TCP Stream. Wireshark akan menampilkan full conversation dalam satu jendela — data merah adalah client, biru adalah server. Ini sangat powerful untuk melihat isi HTTP request/response, credentials dalam plaintext, atau komunikasi malware. Kamu bisa save conversation ke file untuk analisis lebih lanjut.

HTTP Traffic Analysis

Menganalisis request, response, headers, cookies, dan deteksi ancaman pada traffic HTTP.

ℹ️
HTTP vs HTTPS: HTTP berjalan di port 80 dan tidak terenkripsi — semua data bisa dibaca di Wireshark. HTTPS (port 443) menggunakan TLS untuk enkripsi sehingga payload tidak terbaca tanpa private key. Bagian ini fokus pada HTTP plaintext.

Ini adalah contoh kenapa HTTPS wajib untuk semua aplikasi. Sebagai security analyst, ini adalah temuan kritis yang harus segera dilaporkan.

Analisis HTTP di Wireshark

📊 HTTP Statistics
Menu Statistics → HTTP → Requests menampilkan summary semua HTTP request: domain yang dikunjungi, method, dan response code. Sangat berguna untuk get overview cepat.
📦 File Extraction
Menu File → Export Objects → HTTP memungkinkan ekstraksi file yang ditransfer via HTTP: gambar, dokumen, executable, dll. Berguna untuk malware analysis.
🔍 Follow HTTP Stream
Right-click HTTP packet → Follow → HTTP Stream untuk melihat full HTTP conversation termasuk request headers, body, response headers, dan response body dalam satu tampilan.

DNS Tunneling — Teknik Exfiltration yang Tersembunyi

⚠️ DNS Tunneling Indicators

DNS tunneling menyembunyikan data exfiltration dalam DNS query. Data dienkodekan dalam subdomain query yang sangat panjang dan dikirim ke attacker-controlled nameserver.

DNS Tunneling — suspicious queries
# Normal DNS query:

# DNS Tunnel query (data exfiltration encoded):
dGhpcyBpcyBzZWNyZXQgZGF0YQ==.attacker-c2.xyz
aGhpcyBpcyBzZWNyZXQgZGF0YQ==.attacker-c2.xyz
c29tZW1vcmVkYXRhaGVyZQ==.attacker-c2.xyz

# Filter di Wireshark:
dns.qry.name.len > 50 # Query sangat panjang
dns and frame.len > 300 # DNS packet oversized
DNS tunneling menggunakan enkoding Base64 atau hex dalam subdomain. Tanda-tanda: query name sangat panjang (>50 karakter), jumlah DNS query abnormal tinggi ke satu domain, domain random/tidak dikenal, TXT record yang besar.

Suspicious DNS Indicators

🚨 DGA Domains
Domain Generation Algorithm — malware membuat domain random: xkq7wf3nm.com, b4r9znq.net. Filter: dns.qry.name matches "[a-z]{15,}\.(com|net|org)"
⚠️ Excessive Queries
Satu host melakukan ratusan DNS query per menit ke domain berbeda = indikator malware beaconing atau DNS tunneling. Gunakan Statistics → DNS untuk analisis.
🔍 NXDOMAIN Flood
Banyak response NXDOMAIN (domain tidak ada) = DGA malware mencoba menemukan C2 domain aktif. Filter: dns.flags.rcode == 3

HTTPS & TLS Analysis

Memahami TLS handshake, enkripsi, dan apa yang masih bisa dianalisis dari traffic HTTPS.

🔒
Reality Check: Traffic HTTPS terenkripsi — kamu TIDAK bisa membaca payload (request body, response data) tanpa private key server. NAMUN, masih banyak informasi berharga yang bisa dianalisis: IP tujuan, SNI (domain name), versi TLS, cipher suite, ukuran packet, dan timing.

Server Finished [Change Cipher Spec]

Yang Masih Bisa Dianalisis dari HTTPS

✅ Masih Terlihat
  • SNI — domain name tujuan di Client Hello
  • IP Address tujuan koneksi
  • TLS version (TLS 1.2 vs 1.3)
  • Cipher suite yang digunakan
  • Certificate info (Issuer, Subject, validity)
  • Packet size & timing patterns
  • Connection duration & data volume
❌ Tidak Terlihat (Encrypted)
  • HTTP request path (/login, /api/data)
  • HTTP headers (Cookie, Authorization)
  • Request body (POST data, credentials)
  • Response body (HTML, JSON, files)
  • Query strings (?user=admin)

// 10 — Malware Analysis

Malware Traffic Analysis

Identifikasi Indicators of Compromise (IOC), pola beaconing, C2 traffic, dan anomali jaringan yang mengindikasikan infeksi malware.

🔬
ANALYST NOTE: Selalu analisis PCAP malware di environment terisolasi (VM, sandbox). Jangan buka file yang ter-ekstrak dari PCAP malware di komputer utama. Gunakan REMnux atau FlareVM yang didesain untuk malware analysis.

Indicators of Compromise (IOC) dalam Traffic

🔴 C2 Beaconing Traffic

Malware yang terinfeksi secara periodik "check-in" ke C2 server untuk menerima instruksi. Ciri khas beaconing:

  • • Interval yang sangat reguler (misalnya setiap 60 detik persis)
  • • Request ke IP/domain yang tidak dikenal
  • • Ukuran packet yang konsisten (beaconing payload seragam)
  • • Traffic di luar jam kerja (saat user tidak aktif)
Beaconing Pattern
02:14:00.001 192.168.1.105 → 185.220.101.47:443 [TLS] 214 bytes
02:15:00.003 192.168.1.105 → 185.220.101.47:443 [TLS] 214 bytes
02:16:00.001 192.168.1.105 → 185.220.101.47:443 [TLS] 214 bytes
↑ Interval: exactly 60s, same payload size = BEACONING
🟠 Data Exfiltration

Data exfiltration adalah proses pencurian data keluar dari jaringan. Tanda-tandanya:

  • • Upload yang sangat besar ke IP external yang tidak dikenal
  • • Outbound traffic ke cloud storage unusual (non-standard ports)
  • • DNS query dengan subdomain sangat panjang (DNS tunneling)
  • • ICMP packet yang sangat besar (ICMP tunneling)
# Filter traffic upload besar (data keluar)
ip.src == 192.168.1.0/24 and frame.len > 1400

# Cari DNS tunneling (query panjang)
dns.qry.name.len > 50

# ICMP dengan payload besar
icmp and data.len > 64
🟡 Port Scan Detection

Reconnaissance sebelum serangan — attacker memetakan port yang terbuka:

Port Scan Pattern (nmap -sS)
# SYN scan — banyak SYN ke port berbeda dari satu source
10.0.0.50 → 10.0.0.1:22 [SYN]
10.0.0.50 → 10.0.0.1:23 [SYN]
10.0.0.50 → 10.0.0.1:25 [SYN]
10.0.0.50 → 10.0.0.1:80 [SYN]
10.0.0.50 → 10.0.0.1:443 [SYN]
10.0.0.1 → 10.0.0.50:22 [RST,ACK] ← Port closed
10.0.0.1 → 10.0.0.50:80 [SYN,ACK] ← Port OPEN!

# Filter untuk deteksi: banyak SYN tanpa ACK dari satu IP
tcp.flags.syn == 1 and tcp.flags.ack == 0 and ip.src == 10.0.0.50

Malware Traffic Scenarios

Emotet-style Banking Trojan Traffic Pattern

Emotet terkenal dengan multi-stage infection — initial dropper mengunduh payload tambahan, lalu C2 communication dimulai.

Emotet Traffic IOCs
# Stage 1: Initial dropper download via HTTP
GET /wp-content/uploads/2024/invoice.doc HTTP/1.1
Host: compromised-wordpress.com

# Stage 2: Payload download (Emotet DLL)
GET /gate.php HTTP/1.1
Host: 185.220.xx.xx

# Stage 3: C2 Beaconing
POST /gate.php HTTP/1.1
Host: 185.220.xx.xx
Content-Type: application/x-www-form-urlencoded
data=base64encodeddata...
Cari HTTP POST ke IP addresses (bukan domain) — malware sering langsung ke IP untuk menghindari DNS blocking. Filter: http.request.method == "POST" and not http.host matches "[a-zA-Z]"

Ransomware Network Indicators

Ransomware modern sering melakukan reconnaissance dan lateral movement sebelum enkripsi.

Phase 1: Reconnaissance
• SMB scanning (port 445) ke seluruh subnet
• LDAP queries untuk enumerate domain users
• RDP (port 3389) enumeration
Filter: tcp.port == 445 and tcp.flags.syn==1
Phase 2: Lateral Movement
• Pass-the-Hash via SMB (port 445)
• Psexec traffic patterns
• WMI remote execution
Filter: smb or smb2
Phase 3: Exfiltration (pre-encrypt)
• Large data transfer ke cloud/external IP
• FTP/SFTP ke unknown destination
• Mega, rclone traffic patterns
Filter: ftp-data or tcp.port == 21
Phase 4: C2 & Ransom Note
• Connection ke .onion via Tor
• HTTP POST ke ransom payment site
• Key exchange untuk enkripsi
Filter: tcp.port == 9001 or tcp.port == 9030

RAT (Remote Access Trojan) Traffic

RAT memberikan kontrol penuh attacker atas victim machine melalui koneksi persistent.

RAT Traffic Characteristics
# RAT biasanya menggunakan TCP custom protocol
# atau HTTP/HTTPS untuk bypass firewall

# Indikator umum RAT:
1. Koneksi keluar pada port tidak biasa (4444, 1234, 31337)
2. Koneksi ke IP address langsung (bukan domain)
3. Persistent connection yang tidak putus (TCP keepalive)
4. Interactive traffic (ketik perintah → response)
5. Screenshot/keylogger data (regular upload)

# Filter port tidak biasa
tcp.port == 4444 or tcp.port == 1234 or tcp.port == 31337

# Filter koneksi langsung ke IP (no DNS resolution)
# Analisis via Statistics → Endpoints → TCP

// 13 — Best Practices

Best Practices

Panduan etika, legalitas, dan workflow profesional dalam menggunakan Wireshark.

Penggunaan Legal & Etis

Sebelum melakukan packet capture di jaringan manapun selain milik pribadi, dapatkan izin tertulis dari pemilik jaringan atau atasan yang berwenang. Dalam konteks profesional, ini termasuk Rules of Engagement (RoE) yang mendefinisikan scope dan batasan aktivitas.
File PCAP bisa mengandung informasi sangat sensitif: password, cookies, email, dokumen. Simpan di lokasi yang aman, enkripsi jika perlu, dan hapus setelah tidak dibutuhkan sesuai kebijakan retensi data organisasi.
Berbagai regulasi mengatur intercepting network traffic: GDPR (EU), CFAA (US), UU ITE (Indonesia). Packet capture traffic orang lain tanpa izin bisa melanggar hukum pidana. Dalam enterprise, biasanya ada kebijakan IT yang mengatur penggunaan network analyzer.
Untuk pembelajaran dan testing, selalu gunakan VM atau jaringan terisolasi. GNS3, VirtualBox, VMware Workstation bisa membuat virtual network lab yang sepenuhnya aman untuk bereksperimen tanpa risiko.

Workflow Profesional

Selalu catat: tanggal/waktu capture, interface yang digunakan, capture filter yang diterapkan, tujuan capture, dan siapa yang melakukan. Ini penting untuk bukti forensik dan laporan. Tambahkan komentar pada packet penting menggunakan Edit → Packet Comment.
File PCAP bisa sangat besar — gunakan ring buffer untuk capture panjang, pisahkan berdasarkan waktu atau ukuran, dan beri nama file yang deskriptif (tanggal_interface_tujuan.pcapng). Kompresi dengan gzip bisa mengurangi ukuran file hingga 90%.
Selalu mulai analisis dari Statistics: Protocol Hierarchy → Conversations → Endpoints → I/O Graph. Ini memberikan gambaran besar sebelum masuk ke analisis packet individual. Cari anomali yang menonjol sebelum drilling down.
Wireshark punya built-in coloring rules — packet error berwarna merah/hitam, TCP problems kuning, dsb. Kamu bisa customisasi via View → Coloring Rules untuk highlight IOC tertentu secara otomatis. Ini sangat membantu saat analisis PCAP besar.

Performance Tips

⚡ Gunakan Capture Filter
Capture filter mengurangi data yang disimpan sebelum masuk Wireshark — lebih efisien dari display filter. Gunakan saat kamu tahu protocol/IP yang mau dicapture. Contoh: tcp port 80
💾 Aktifkan Ring Buffer
Untuk capture jangka panjang, aktifkan ring buffer (Capture Options → Output) dengan batas ukuran per file. Wireshark akan overwrite file lama, menjaga storage terkontrol.
🛑 Stop Resolusi Nama
View → Name Resolution → matikan "Resolve Network Addresses" jika tidak diperlukan. DNS reverse lookup untuk setiap IP bisa sangat memperlambat Wireshark pada traffic padat.

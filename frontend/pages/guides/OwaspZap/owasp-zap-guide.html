// 01 — Apa itu OWASP ZAP?

Apa itu OWASP ZAP?

OWASP ZAP (Zed Attack Proxy) adalah security scanner open-source yang dirancang khusus untuk menemukan kerentanan di aplikasi web. Dikembangkan oleh OWASP (Open Web Application Security Project) dan dikelola oleh komunitas global.

🕷️ Spider/Crawler
Menjelajahi seluruh halaman dan endpoint dari aplikasi web secara otomatis untuk membangun site map yang komprehensif.
🔍 Active Scanner
Mengirimkan request berbahaya ke target untuk mendeteksi kerentanan seperti SQL Injection, XSS, SSRF, dan ratusan lainnya.
👁️ Passive Scanner
Menganalisis request/response HTTP yang lewat tanpa mengirim request tambahan — tidak invasif dan aman untuk production.
🔄 Intercepting Proxy
Bertindak sebagai man-in-the-middle untuk intercept, inspect, dan modify request/response HTTP/HTTPS secara real-time.
📜 Zest Scripting
Bahasa scripting JSON-based untuk mengotomatiskan pengujian keamanan — bisa digunakan untuk custom attack rules dan automation.
📊 Report Generator
Menghasilkan laporan kerentanan dalam format HTML, JSON, XML, dan Markdown dengan detail CVSS scoring dan rekomendasi remediasi.
ℹ️

Konteks Penggunaan Legal: ZAP adalah tool yang sah dan diakui oleh industri keamanan siber. Tool ini digunakan oleh ribuan penguji keamanan profesional (penetration tester) di seluruh dunia. Yang menentukan legalitasnya adalah siapa yang menjadi target pengujian dan apakah ada izin eksplisit dari pemilik sistem.

Komponen Utama OWASP ZAP

🖥️ ZAP Desktop (GUI)
Aplikasi desktop dengan antarmuka grafis lengkap — ideal untuk pengujian manual dan eksplorasi interaktif. Tersedia untuk Windows, Linux, dan macOS.
💻 ZAP CLI / API
REST API dan command-line interface untuk mengotomatiskan pengujian keamanan dalam pipeline CI/CD. Sempurna untuk DevSecOps workflow.
🐳 ZAP Docker
Image Docker resmi untuk menjalankan ZAP dalam container — memudahkan integrasi dengan GitHub Actions, Jenkins, GitLab CI, dan platform CI/CD lainnya.
🔌 Add-ons
Marketplace add-on untuk memperluas kemampuan ZAP: Active Scan Rules, GraphQL Scanner, OpenAPI Support, JWT Analyzer, dan puluhan lainnya.
// 02 — Instalasi OWASP ZAP

Instalasi OWASP ZAP

Download & Instalasi

1
Buka zaproxy.org/download dan unduh ZAP 2.x.x Windows (64) Installer.
2
Jalankan installer sebagai Administrator dan ikuti wizard instalasi.
3
ZAP memerlukan Java 11+ — installer sudah menyertakan bundled JRE, namun bisa install manual jika perlu.
Command Prompt / PowerShell
# Verifikasi Java tersedia
C:\> java -version openjdk version "17.0.x"
# Jalankan ZAP dari CLI (opsional)
C:\> "C:\Program Files\ZAP\Zed Attack Proxy\zap.bat" -daemon -port 8080
💡

Di Windows, ZAP juga dapat diinstal via Chocolatey: choco install zap atau via Winget: winget install ZAP.ZAP

🐧 Linux (Debian/Ubuntu)

Terminal — bash
# Install Java 17+ terlebih dahulu
$ sudo apt update && sudo apt install default-jdk -y

# Download ZAP package
$ wget https://github.com/zaproxy/zaproxy/releases/latest/download/ZAP_Linux.tar.gz

# Ekstrak
$ tar -xzf ZAP_Linux.tar.gz

# Jalankan ZAP
$ ./ZAP_*/zap.sh

# Atau jalankan headless (daemon mode)
$ ./zap.sh -daemon -host 0.0.0.0 -port 8080
💡

Di Kali Linux, ZAP sudah tersedia di repository: sudo apt install zaproxy

🍎 macOS via Homebrew

Terminal — zsh
# Install via Homebrew Cask
% brew install --cask owasp-zap

# Verifikasi instalasi
% zap.sh -version ZAP 2.x.x

🐳 Docker (Rekomendasi untuk CI/CD)

Terminal — Docker
# Pull image ZAP terbaru
$ docker pull ghcr.io/zaproxy/zaproxy:stable

# Jalankan ZAP sebagai daemon
$ docker run -d -p 8080:8080 ghcr.io/zaproxy/zaproxy:stable zap.sh -daemon -host 0.0.0.0 -port 8080

# Jalankan Baseline Scan langsung
$ docker run --rm ghcr.io/zaproxy/zaproxy:stable zap-baseline.py -t https://target.example.com

# Full scan dengan laporan HTML
$ docker run -v $(pwd):/zap/wrk/:rw ghcr.io/zaproxy/zaproxy:stable zap-full-scan.py -t https://target.example.com -r report.html
ℹ️

Tiga jenis scan script Docker ZAP:
• zap-baseline.py — Passive scan saja, aman untuk production
• zap-api-scan.py — Scan REST/GraphQL API via OpenAPI spec
• zap-full-scan.py — Active + Passive scan, jangan di production!

⚠️

Kebutuhan Java: ZAP memerlukan Java 11 atau lebih baru. Gunakan perintah java -version untuk memverifikasi. Jika belum ada, download dari adoptium.net (Eclipse Temurin JDK).

// 03 — Konfigurasi Proxy Browser

Konfigurasi Proxy Browser

ZAP bekerja sebagai intercepting proxy — browser harus dikonfigurasi untuk mengirim traffic melalui ZAP agar request/response dapat dianalisis.

🔧 Setup Manual Browser

🦊 Firefox

Settings → Network Settings → Manual proxy configuration:


HTTP Proxy: 127.0.0.1   Port: 8080

Atau gunakan: FoxyProxy Extension untuk toggle cepat

🌐 Chrome / Edge

Chrome menggunakan proxy sistem. Gunakan flag startup:


chrome --proxy-server="http://127.0.0.1:8080"

Atau gunakan: SwitchyOmega Extension

📜 Install ZAP Root Certificate (untuk HTTPS)

Agar ZAP bisa mendekripsi HTTPS traffic, browser harus mempercayai sertifikat CA ZAP:

1
Di ZAP: Tools → Options → Network → Server Certificates → Save → simpan file zap_root_ca.cer
2
Firefox: Settings → Privacy & Security → View Certificates → Import → pilih file cert ZAP
3
Chrome/Windows: Klik kanan file .cer → Install Certificate → Local Machine → Trusted Root CAs
4
Buka browser yang sudah dikonfigurasi proxy, akses http://zap untuk memverifikasi koneksi ke ZAP berhasil.
💡

Tip Cepat: ZAP menyediakan shortcut URL khusus: browse ke http://zap (bukan www.zap.com) dan ZAP akan otomatis menawarkan download sertifikat CA-nya untuk browser Anda.

🔧 ZAP Default Ports

Komponen Port Default Keterangan
HTTP/HTTPS Proxy 8080 Port utama untuk traffic dari browser — bisa diubah di Options → Network → Local Servers
ZAP API 8080 REST API untuk automasi — aktifkan di Options → API (butuh API key di production)
Ajax Spider — Menggunakan browser lokal (Selenium) — tidak perlu port terpisah
// 04 — Spider Scan

Spider Scan — Site Discovery

Spider adalah crawler yang menjelajahi aplikasi web secara otomatis untuk membangun site map. ZAP memiliki dua jenis spider: Traditional Spider dan AJAX Spider.

🕸️ Traditional Spider
Mengikuti link HTML statis (href, form action, srcset). Cepat tapi tidak bisa mengeksekusi JavaScript — melewatkan SPA/React/Vue apps. Cocok untuk aplikasi web tradisional.
⚡ AJAX Spider
Menggunakan browser headless (Selenium/ChromeDriver) untuk mengeksekusi JavaScript dan menemukan link yang di-render secara dinamis. Lebih lambat tapi jauh lebih komprehensif untuk SPA.

🕷️ Menjalankan Spider via ZAP GUI

1
Klik kanan URL di Sites tree (panel kiri ZAP) → Attack → Spider
2
Set Starting Point ke URL target (contoh: http://testapp.local)
3
Atur Max Depth (rekomendasi: 5) dan Max Children untuk membatasi scope
4
Klik Start Scan → pantau progres di tab Spider bawah ZAP

💻 Spider via ZAP CLI/API

Terminal — ZAP CLI
# Jalankan Spider via ZAP API (ZAP harus sudah berjalan)
$ curl "http://localhost:8080/JSON/spider/action/scan/?apikey=yourApiKey&url=http://target.local"

# Cek status Spider scan
$ curl "http://localhost:8080/JSON/spider/view/status/?scanId=0" {"status": "75"}
# Lihat hasil URLs yang ditemukan
$ curl "http://localhost:8080/JSON/spider/view/results/?scanId=0"
✅

Tips Spider Efektif: Untuk aplikasi yang memerlukan login, lakukan manual browse terlebih dahulu (buka browser, login manual dengan ZAP proxy aktif), baru jalankan Spider. ZAP akan menyertakan session cookies secara otomatis.

// 05 — Active Scan

Active Scan — Vulnerability Detection

Active Scan secara aktif mengirim payload pengujian ke target untuk mendeteksi kerentanan nyata. Ini adalah fase invasif — HANYA jalankan di sistem yang Anda miliki atau ada izin tertulis.

🚫

PERINGATAN KERAS: Active Scan MENGIRIM payload berbahaya (SQLi, XSS, dll) ke target. Ini dapat merusak data, menyebabkan downtime, dan jelas ILEGAL jika dilakukan tanpa izin. Selalu gunakan di lab/staging environment atau dengan izin tertulis pemilik sistem.

⚙️ Jenis Kerentanan yang Dideteksi Active Scan

HIGH
  • SQL Injection
  • Remote Code Execution
  • Path Traversal
  • Server-Side Request Forgery
  • XML External Entity (XXE)
MEDIUM
  • Cross-Site Scripting (XSS)
  • CSRF (Cross-Site Request Forgery)
  • Insecure Direct Object Reference
  • Open Redirect
  • Command Injection
LOW
  • Missing Security Headers
  • Insecure Cookie Flags
  • Information Disclosure
  • Verbose Error Messages
  • Outdated Libraries (passive)

🔥 Menjalankan Active Scan

1
Pastikan site sudah di-spider terlebih dahulu — Active Scan membutuhkan site map yang lengkap.
2
Klik kanan node di Sites tree → Attack → Active Scan
3
Di dialog Active Scan, pilih Policy (Default Policy atau custom) dan Recurse untuk scan seluruh subtree.
4
Klik Start Scan — pantau progress di tab Active Scan dan Alerts.
Active Scan via ZAP API
# Mulai Active Scan
$ curl "http://localhost:8080/JSON/ascan/action/scan/?apikey=yourKey&url=http://target.local&recurse=true" {"scan": "0"}
# Monitor progress Active Scan (0-100%)
$ curl "http://localhost:8080/JSON/ascan/view/status/?scanId=0" {"status": "42"}
# Lihat alerts yang ditemukan
$ curl "http://localhost:8080/JSON/core/view/alerts/?baseurl=http://target.local"

⚙️ Scan Policy — Mengatur Agresivitas

Policy Level Deskripsi Rekomendasi
Default Policy Semua rules aktif dengan threshold default. Komprehensif untuk kebanyakan kebutuhan. ✅ Penggunaan umum
Light (custom) Hanya rules risiko tinggi, strength rendah. Cepat, false positive minimal. ✅ Production/staging sensitif
Insane (custom) Semua rules, strength maksimal. Sangat lambat, banyak request. ⚠️ Lab environment saja
// 06 — Passive Scan

Passive Scan — Non-Invasive Analysis

Passive Scan menganalisis setiap request/response HTTP yang melewati ZAP proxy tanpa mengirim request tambahan. Ini berarti tidak ada risiko merusak aplikasi atau data.

✅ Yang Dideteksi Passive Scan
  • Missing X-Frame-Options header
  • Missing Content-Security-Policy
  • Cookie tanpa HttpOnly/Secure flag
  • Penggunaan HTTP (non-HTTPS)
  • Versi library yang expose di header
  • MIME type sniffing issues
  • Timestamp disclosure
ℹ️ Cara Menggunakan

Passive Scan berjalan otomatis setiap saat saat ada traffic melewati ZAP. Untuk memaksimalkan coverage:


  1. Konfigurasi browser menggunakan ZAP sebagai proxy
  2. Browse aplikasi secara manual — klik semua fitur, login, logout
  3. Cek tab Alerts di ZAP untuk melihat temuan
  4. Export laporan ke HTML/JSON
✅

Passive Scan aman untuk production: Karena tidak mengirim request tambahan, Passive Scan bisa digunakan di environment production tanpa risiko merusak data atau menyebabkan downtime. Ini adalah cara paling aman untuk memulai security testing.

// 07 — Alert Analysis

Memahami Alert ZAP

ZAP mengategorikan temuan kerentanan sebagai "Alerts" dengan level risiko dari High hingga Informational. Berikut panduan interpretasi setiap alert.

Tingkat Risiko Alert

HIGH

Kerentanan kritis yang harus segera diperbaiki. Bisa menyebabkan akses tidak sah, pencurian data, atau eksekusi kode. Contoh: SQL Injection, RCE, XXE.

MEDIUM

Kerentanan signifikan yang perlu ditangani. Bisa dieksploitasi dalam kondisi tertentu. Contoh: XSS Reflected, CSRF, Open Redirect.

LOW / INFO

Masalah konfigurasi atau informational. Tidak langsung berbahaya tapi bisa membantu attacker. Contoh: Missing headers, verbose error messages.

SQL Injection — HIGH
SQL Injection📋 copy
Attacker bisa menyisipkan SQL query berbahaya melalui input field untuk membaca/memodifikasi database.
Payload: ' OR 1=1-- | 1' AND SLEEP(5)-- | UNION SELECT ...
🎯 Temuan: Cek URL params, form fields, search boxes, login forms.
Cross-Site Scripting — MEDIUM
Cross Site Scripting (Reflected)📋 copy
Script berbahaya dieksekusi di browser korban. Reflected: dari URL. Stored: tersimpan di database.
Payload: <script>alert(1)</script> | <img src=x onerror=alert(1)>
🎯 Temuan: Input yang di-reflect ke halaman tanpa encoding yang tepat.
CSRF — MEDIUM
Absence of Anti-CSRF Tokens📋 copy
Form aksi penting (transfer, ganti password) tidak memiliki CSRF token — rentan terhadap serangan cross-site request.
Fix: Tambahkan CSRF token pada setiap form yang mengubah state.
🎯 Cek: Form POST tanpa token tersembunyi atau header X-CSRF-Token.
Path Traversal — HIGH
Path Traversal📋 copy
Attacker dapat mengakses file di luar direktori web root dengan manipulasi path seperti ../../etc/passwd.
Payload: /../../../etc/passwd | ..%2F..%2Fetc%2Fshadow
🎯 Cek: Parameter filename, include, path di URL/form.
Missing Header — LOW
X-Frame-Options Header Not Set📋 copy
Halaman dapat dimuat dalam iframe oleh website lain — rentan terhadap serangan Clickjacking.
Fix: Header X-Frame-Options: DENY atau Content-Security-Policy: frame-ancestors 'none'
🎯 Berlaku untuk semua halaman sensitif (login, transaksi).
Cookie Security — LOW
Cookie Without HttpOnly Flag📋 copy
Cookie sensitif (session) bisa dibaca oleh JavaScript — memungkinkan pencurian session via XSS.
Fix: Set-Cookie: session=abc; HttpOnly; Secure; SameSite=Strict
🎯 Cek semua cookie yang mengandung session/auth token.
Missing Header — MEDIUM
Content Security Policy Not Set📋 copy
Tanpa CSP, browser tidak tahu script mana yang boleh dieksekusi — memudahkan eksploitasi XSS.
Fix: Content-Security-Policy: default-src 'self'; script-src 'self'
🎯 Berlaku untuk semua halaman aplikasi web.
Information Disclosure — INFO
Server Leaks Information via "X-Powered-By"📋 copy
Header response mengungkapkan teknologi/versi server — membantu attacker mencari CVE yang sesuai.
Contoh: X-Powered-By: PHP/7.4.3 | Server: Apache/2.4.41
🎯 Fix: Hapus atau samarkan header Server dan X-Powered-By.
Open Redirect — MEDIUM
URL Redirection to Untrusted Site📋 copy
Parameter URL dapat dialihkan ke domain eksternal tanpa validasi — bisa digunakan untuk phishing.
Contoh: /redirect?url=http://evil.com | ?next=//evil.com
🎯 Cek: Parameter redirect, return_url, next, callback di URL.
// 08 — Authentication Testing

Authentication & Session Testing

Menguji keamanan mekanisme autentikasi, manajemen sesi, dan kontrol akses — area yang paling sering memiliki kerentanan kritis.

🔐 Setup Authentication di ZAP

1
Buka Sites → klik kanan target → Context → Include in Context untuk membuat context baru.
2
Di Context, buka Authentication → pilih type: Form-Based Authentication, JSON Authentication, atau Script-Based.
3
Isi Login URL, Username Parameter, dan Password Parameter sesuai form login target.
4
Set Logged In Indicator (string yang hanya muncul saat login, misal "Logout") dan Logged Out Indicator.
5
Tambahkan User di Context → Users dengan username dan password yang valid.
6
Jalankan Spider/Active Scan dengan User yang telah dikonfigurasi — ZAP akan otomatis login ulang jika sesi expired.

🎯 Kerentanan Autentikasi yang Umum

🔑 Broken Authentication
  • Password tidak ada rate limiting → brute force
  • Session ID mudah diprediksi
  • Session tidak di-invalidate saat logout
  • Session tidak expire otomatis
  • Session ID dikirim via URL (bukan cookie)
🚪 Broken Access Control
  • IDOR — akses resource orang lain via ID
  • Privilege escalation horizontal/vertikal
  • Endpoint admin accessible tanpa login
  • Directory listing enabled
  • Missing function level access control
// 09 — ZAP Scripting (Zest)

ZAP Scripting & Automation

ZAP mendukung beberapa jenis skrip untuk mengotomatiskan dan mengustomisasi pengujian keamanan. Zest adalah bahasa scripting JSON-based milik ZAP, namun juga mendukung JavaScript, Groovy, Python, dan Ruby.

📜 Jenis Skrip ZAP

Jenis Skrip Fungsi Use Case
Active Rules Tambahkan rules custom untuk Active Scan Deteksi kerentanan spesifik aplikasi yang tidak ada di default rules
Passive Rules Analisis response tanpa kirim request Deteksi informasi sensitif dalam response headers/body
Authentication Custom login flow MFA, CAPTCHA, OAuth, SSO dengan flow kompleks
Proxy Intercept dan modify request/response Tambah header, modifikasi parameter, inject token
Standalone Script yang dijalankan manual Automasi tugas berulang, setup environment

🐍 Contoh Python Script via ZAP API

Python — ZAP API Automation
#!/usr/bin/env python3
# pip install python-owasp-zap-v2.4
$ pip install python-owasp-zap-v2.4

from zapv2 import ZAPv2 import time target = 'http://testapp.local' apiKey = 'your-api-key' zap = ZAPv2(apikey=apiKey, proxies={'http': 'http://127.0.0.1:8080'}) # Akses target untuk memastikan sudah ada di Sites zap.urlopen(target) # Jalankan Spider scanId = zap.spider.scan(target) while int(zap.spider.status(scanId)) < 100: print(f"Spider: {zap.spider.status(scanId)}%") time.sleep(2) # Jalankan Active Scan scanId = zap.ascan.scan(target) while int(zap.ascan.status(scanId)) < 100: print(f"Scan: {zap.ascan.status(scanId)}%") time.sleep(5) # Export laporan HTML with open('report.html', 'w') as f: f.write(zap.core.htmlreport()) print("Selesai! Laporan disimpan di report.html")
// 10 — Etika & Risiko Penggunaan

Etika & Risiko Penggunaan

🚫

ILEGAL — JANGAN LAKUKAN: Menggunakan ZAP atau tool security testing lainnya pada aplikasi web, server, atau sistem yang bukan milik Anda tanpa izin eksplisit adalah tindakan ILEGAL di Indonesia (UU ITE No. 19 Tahun 2016 Pasal 30) dan bisa dikenakan pidana penjara hingga 8 tahun dan denda hingga 800 juta rupiah.

✅ BOLEH dilakukan
  • Scan aplikasi web milik sendiri yang Anda kembangkan
  • Scan di lingkungan lab virtual (DVWA, WebGoat, Juice Shop)
  • Scan dengan izin tertulis dari pemilik sistem
  • Bug bounty program yang mengizinkan automated scanning
  • Scan di platform legal: HackTheBox, TryHackMe, PortSwigger Labs
❌ TIDAK BOLEH dilakukan
  • Scan website/aplikasi orang lain tanpa izin
  • Scan aplikasi perusahaan dari luar tanpa kontrak resmi
  • Scan infrastruktur pemerintah atau perbankan
  • Menggunakan hasil scan untuk eksploitasi atau pencurian data
  • Menjual data kerentanan kepada pihak ketiga tanpa izin pemilik

⚡ Risiko Teknis yang Perlu Diketahui

💥 DoS Tidak Disengaja
Active Scan yang agresif bisa menyebabkan server kewalahan (overload) karena mengirim ratusan request per detik. Selalu batasi thread dan delay di Scan Policy.
🗄️ Data Corruption
Payload SQL Injection atau form manipulation bisa memodifikasi atau menghapus data di database. JANGAN scan production tanpa backup yang verified.
🚨 Memicu WAF/IDS Alert
Active Scan akan terdeteksi oleh WAF, IDS/IPS, dan monitoring system. Di lingkungan dengan tim security aktif, ini bisa menyebabkan incident response yang tidak perlu.
// 11 — Best Practice Security Testing

Best Practice — Pengujian yang Bertanggung Jawab

Checklist Sebelum Testing
✅ Dapatkan izin tertulis (Rules of Engagement) dari pemilik sistem ✅ Definisikan scope: URL apa yang boleh/tidak boleh di-test ✅ Gunakan environment testing/staging, bukan production ✅ Backup database/data sebelum Active Scan ✅ Koordinasikan jadwal testing dengan tim ops/dev ✅ Gunakan akun test yang terpisah, bukan akun production ✅ Simpan log semua activity untuk dokumentasi ✅ Siapkan procedure untuk melaporkan critical finding segera

⚙️ Konfigurasi ZAP yang Aman

Setting Nilai Rekomendasi Keterangan
Active Scan Threads 2-5 Default 2 cukup untuk kebanyakan kasus. Tingkatkan hanya di lab environment.
Delay Between Requests 100-500ms Mencegah overload server target. Set di Scan Policy → Options.
Request Timeout 20 detik Jangan terlalu pendek — beberapa endpoint memang lambat.
Max Alerts Per Rule 10-50 Membatasi duplikat alert untuk jenis kerentanan yang sama.
Spider Max Depth 5 Mencegah crawling yang terlalu dalam dan memakan waktu lama.
🎯

Responsible Disclosure: Setelah menemukan kerentanan, laporkan ke pemilik sistem secara private (bukan publik) dan berikan waktu yang cukup (biasanya 90 hari) untuk perbaikan sebelum dipublikasikan. Ini adalah praktik coordinated vulnerability disclosure yang etis.

// 13 — Latihan Praktik

Mini Latihan Praktik Bertahap

🏗️

Lab Environment: Semua latihan di bawah menggunakan aplikasi web yang memang dirancang untuk diuji. JANGAN gunakan teknik ini di aplikasi nyata tanpa izin. Install lab di lokal: DVWA (Docker), OWASP Juice Shop (Docker), atau gunakan portswigger.net/web-security (online, gratis).

1
Passive Scan & Report — Juice Shop
Beginner

Tujuan: Kenali interface ZAP dan lakukan Passive Scan pertama menggunakan OWASP Juice Shop.

1
Install OWASP Juice Shop: docker run -d -p 3000:3000 bkimminich/juice-shop
2
Buka ZAP → pastikan proxy aktif di port 8080. Konfigurasi browser menggunakan proxy ZAP.
3
Browse Juice Shop (http://localhost:3000) secara manual — klik semua menu, login sebagai guest.
4
Lihat tab Alerts di ZAP — catat semua alert yang sudah ditemukan Passive Scan.
5
Generate laporan: Report → Generate Report → HTML → simpan dan buka di browser.
🎯
Sukses jika Anda bisa menghasilkan laporan HTML dengan setidaknya 5 alert dan memahami arti masing-masing.
2
Spider Scan — Menemukan Semua Endpoint
Beginner

Tujuan: Gunakan Spider untuk menemukan semua endpoint di Juice Shop.

1
Di ZAP, klik kanan http://localhost:3000 di Sites tree → Attack → Spider
2
Jalankan Spider dengan Max Depth: 5, biarkan berjalan hingga selesai.
3
Lihat tab Spider — catat berapa URL yang ditemukan. Bandingkan dengan manual browse.
4
Coba juga AJAX Spider (Tools → AJAX Spider) — bandingkan hasilnya dengan Traditional Spider.
🎯
Sukses jika Anda bisa membandingkan hasil Traditional vs AJAX Spider dan memahami kapan menggunakan masing-masing.
3
Temukan SQL Injection di DVWA
Intermediate

Tujuan: Gunakan Active Scan ZAP untuk mendeteksi SQL Injection di DVWA (Damn Vulnerable Web App).

1
Install DVWA: docker run -d -p 8888:80 vulnerables/web-dvwa → akses http://localhost:8888
2
Login ke DVWA (admin/password) → set Security Level ke Low di DVWA Security.
3
Buka halaman SQL Injection di DVWA melalui browser yang terkonfigurasi proxy ZAP.
4
Di ZAP, klik kanan URL DVWA SQL Injection → Attack → Active Scan.
5
Tunggu scan selesai → lihat alert SQL Injection di tab Alerts dengan detail evidence-nya.
6
Baca alert detail: Evidence, Solution, dan Reference. Dokumentasikan temuan Anda.
🎯
Sukses jika ZAP menemukan alert SQL Injection HIGH dengan evidence payload dan Anda bisa menjelaskan cara remediasinya.
4
Authentication Context & Authenticated Scan
Intermediate

Tujuan: Setup authentication di ZAP dan lakukan scan pada area yang memerlukan login.

1
Browse Juice Shop, lakukan login manual dengan proxy ZAP aktif. Catat URL login form dan parameter.
2
Di ZAP: Manage Contexts → New Context → include URL http://localhost:3000/*
3
Di Context → Authentication: pilih Form-based Authentication → isi Login URL dan parameter.
4
Tambahkan User dengan email/password valid → set Logged In Indicator (misal: "Your Basket").
5
Jalankan Spider dengan context ini → ZAP akan otomatis login dan menjelajahi area authenticated.
🎯
Sukses jika Spider berhasil menemukan endpoint authenticated (basket, profile, orders) yang tidak ditemukan tanpa login.
5
Docker CI/CD Integration — Automated Security Pipeline
Advanced

Tujuan: Integrasikan ZAP ke dalam pipeline CI/CD menggunakan Docker dan GitHub Actions.

1
Buat file .github/workflows/zap-scan.yml di repository Anda.
2
Tambahkan job yang menjalankan Juice Shop Docker, lalu ZAP Baseline Scan terhadapnya.
3
Konfigurasi ZAP untuk upload laporan sebagai artifact GitHub Actions.
4
Set threshold: jika ada alert HIGH, pipeline fails (non-zero exit code).
5
Jalankan workflow dan review laporan HTML yang dihasilkan secara otomatis.
🎯
Sukses jika Pipeline CI/CD Anda otomatis menjalankan ZAP scan pada setiap PR/push dan menghasilkan laporan keamanan.

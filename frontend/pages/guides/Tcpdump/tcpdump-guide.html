// 01 — Apa itu Tcpdump?

Apa itu Tcpdump?

Tcpdump adalah tool command-line untuk packet capture dan analisis jaringan yang berjalan di hampir semua sistem Unix/Linux. Dikembangkan pertama kali pada 1988 oleh Van Jacobson, Craig Leres, dan Steven McCanne, Tcpdump memungkinkan Anda mengintip paket data yang melewati interface jaringan secara real-time.

📡 Packet Capture
Menangkap paket jaringan yang melewati interface secara real-time — TCP, UDP, ICMP, ARP, DNS, HTTP, TLS, dan protokol lainnya.
🔍 Traffic Analysis
Menganalisis isi paket, header, flags, payload — berguna untuk troubleshooting koneksi, debugging DNS, dan deteksi anomali.
🛡️ Security Monitoring
Monitoring defensif jaringan — deteksi scan port, koneksi tidak wajar, traffic mencurigakan, dan traffic plaintext berbahaya.
💾 PCAP Files
Menyimpan capture ke file .pcap yang bisa dibuka ulang di Tcpdump, Wireshark, tshark, Zeek, atau Suricata untuk analisis mendalam.
⚙️ BPF Filters
Menggunakan Berkeley Packet Filter (BPF) — bahasa filter yang sangat powerful untuk memilih paket berdasarkan host, port, protokol, dan kombinasinya.
🔗 Passive Listening
Bekerja secara pasif — hanya mendengarkan tanpa mengirim paket. Berbeda dengan Nmap yang aktif. Tidak mengganggu jaringan.
ℹ️

Tcpdump vs Wireshark: Tcpdump adalah CLI tool — ringan, powerful, dan berjalan di server tanpa GUI. Wireshark adalah GUI tool dengan fitur analisis visual lebih kaya. Keduanya menggunakan library libpcap yang sama dan bisa saling membaca file .pcap.

Passive vs Active Monitoring

👂 Passive Monitoring (Tcpdump)
  • Hanya mendengarkan paket yang lewat
  • Tidak mengirim paket apapun ke jaringan
  • Tidak terdeteksi oleh perangkat lain
  • Tidak mempengaruhi kinerja jaringan
  • Cocok untuk monitoring dan troubleshooting
📤 Active Scanning (Nmap)
  • Mengirim paket ke target untuk mendapat respons
  • Terlihat di log target dan IDS
  • Menghasilkan traffic tambahan
  • Bisa memicu alert keamanan
  • Digunakan untuk discovery dan port scanning
// 02 — Instalasi Tcpdump

Instalasi Tcpdump

🐧 Linux (Debian / Ubuntu)

Terminal — Linux
# Update dan install tcpdump
$ sudo apt update && sudo apt install -y tcpdump

# Verifikasi versi
$ tcpdump --version tcpdump version 4.99.1 libpcap version 1.10.1 (with TPACKET_V3) OpenSSL 3.0.2 15 Mar 2022
# Cek lokasi binary
$ which tcpdump /usr/bin/tcpdump

🐧 Linux (Arch / Manjaro)

Terminal — Arch
$ sudo pacman -S tcpdump

🍎 macOS

Terminal — macOS
# Tcpdump sudah terinstall di macOS secara default
$ tcpdump --version tcpdump version 4.99.4 -- Apple version 108.8
# Atau install versi terbaru via Homebrew
$ brew install tcpdump

🪟 Windows (via WSL)

PowerShell → WSL2
# Aktifkan WSL2 (jalankan sebagai Administrator di PowerShell)
PS> wsl --install

# Di dalam WSL Ubuntu, install tcpdump
$ sudo apt install -y tcpdump

# Alternatif: WinDump (native Windows, butuh Npcap)
# Download Npcap dari: npcap.com
# Download WinDump dari: winpcap.org/windump
⚠️

Hak Akses Root/Sudo: Tcpdump memerlukan akses root/sudo untuk membuka interface jaringan dalam mode promiscuous. Tanpa sudo, Anda tidak bisa capture paket dari interface. Ini adalah fitur keamanan OS, bukan bug.

💡

Tip — Jalankan tanpa sudo setiap saat: Tambahkan user ke grup pcap dan set capabilities pada binary: sudo setcap cap_net_raw,cap_net_admin=eip $(which tcpdump). Namun ini membuka risiko keamanan — hanya lakukan di lab/VM pribadi.

// 03 — Mengetahui Interface & IP

Mengetahui Interface Jaringan & IP

Sebelum capture, Anda perlu mengetahui nama interface jaringan yang aktif, IP address lokal, gateway, dan subnet jaringan rumah Anda.

Melihat Semua Interface Tersedia

List Network Interfaces
# Tampilkan semua interface yang bisa di-capture
$ sudo tcpdump -D 1.eth0 [Up, Running, Connected] 2.wlan0 [Up, Running, Connected] 3.lo [Up, Running, Loopback] 4.docker0 [Up, Running] 5.any (Pseudo-device that captures on all interfaces)
# Alternatif dengan ip command
$ ip addr show 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 inet 192.168.1.105/24 brd 192.168.1.255 scope global eth0
$ ip route show default via 192.168.1.1 dev eth0 proto dhcp 192.168.1.0/24 dev eth0 proto kernel scope link
Interface Keterangan Kapan Digunakan
eth0 / ens33 Interface Ethernet (kabel) Capture trafik jaringan kabel
wlan0 / wlp2s0 Interface WiFi (wireless) Capture trafik WiFi
lo Loopback (127.0.0.1) Capture trafik lokal (antar proses di komputer sama)
any Semua interface sekaligus Capture dari semua interface, tapi tidak support promiscuous mode
docker0 Interface Docker bridge Monitor trafik container Docker
💡

Promiscuous Mode: Defaultnya, interface hanya menerima paket yang ditujukan ke MAC address-nya sendiri. Tcpdump dengan sudo mengaktifkan promiscuous mode — interface menangkap semua paket di segmen jaringan, termasuk broadcast dan multicast.

// 04 — Packet Capture Dasar

Packet Capture Dasar

Pelajari cara menjalankan capture dasar Tcpdump — dari semua traffic hingga filter spesifik per interface, host, port, dan protokol.

4.1 — Capture Semua Traffic

Basic Capture
# Capture semua paket di interface eth0 (Ctrl+C untuk stop)
$ sudo tcpdump -i eth0 tcpdump: verbose output suppressed, use -v or -vv for full protocol decode listening on eth0, link-type EN10MB (Ethernet), snapshot length 262144 bytes 14:32:05.123456 IP 192.168.1.105.52341 > 8.8.8.8.53: UDP, length 28 14:32:05.145678 IP 8.8.8.8.53 > 192.168.1.105.52341: UDP, length 44 14:32:05.160000 IP 192.168.1.105.80 > 192.168.1.1.59821: Flags [S], seq 0, win 64240 ^C 47 packets captured 47 packets received by filter 0 packets dropped by kernel
# Capture dengan output lebih verbose (-v, -vv, -vvv)
$ sudo tcpdump -i eth0 -v
# Tampilkan IP sebagai angka, bukan hostname (lebih cepat)
$ sudo tcpdump -i eth0 -n
# Tampilkan port sebagai angka, bukan nama service
$ sudo tcpdump -i eth0 -nn
# Batasi jumlah paket yang di-capture (10 paket lalu stop)
$ sudo tcpdump -i eth0 -c 10
Flag Fungsi Keterangan
-i eth0 Pilih Interface Tentukan interface yang di-listen. Wajib diisi untuk capture spesifik.
-n No DNS Lookup Tidak resolve IP ke hostname — lebih cepat, output lebih bersih.
-nn No DNS + No Port Name IP dan port ditampilkan sebagai angka. Sangat direkomendasikan.
-v / -vv / -vvv Verbose Tampilkan lebih banyak detail paket. -vvv = paling detail.
-c 100 Count Stop setelah capture N paket. Berguna agar tidak capture terus-menerus.
-e Ethernet Header Tampilkan MAC address source dan destination.
-q Quiet Output minimal — hanya info penting, tanpa detail protokol.

4.2 — Capture Berdasarkan Host/IP

Host Filter
# Capture semua traffic ke/dari router (192.168.1.1)
$ sudo tcpdump -i eth0 -nn host 192.168.1.1

# Capture hanya traffic DARI IP tertentu (source)
$ sudo tcpdump -i eth0 -nn src 192.168.1.100

# Capture hanya traffic KE IP tertentu (destination)
$ sudo tcpdump -i eth0 -nn dst 8.8.8.8

# Capture semua traffic di subnet rumah
$ sudo tcpdump -i eth0 -nn net 192.168.1.0/24

4.3 — Capture Berdasarkan Port

Port Filter
# Capture traffic HTTP (port 80)
$ sudo tcpdump -i eth0 -nn port 80

# Capture traffic DNS (port 53)
$ sudo tcpdump -i eth0 -nn port 53

# Capture range port (port 1 sampai 1024)
$ sudo tcpdump -i eth0 -nn portrange 1-1024

# Capture traffic dari port tertentu (source port)
$ sudo tcpdump -i eth0 -nn src port 443

# Capture ke port tertentu (destination port)
$ sudo tcpdump -i eth0 -nn dst port 22

4.4 — Capture Berdasarkan Protokol

Protocol Filter
# Capture hanya paket TCP
$ sudo tcpdump -i eth0 -nn tcp

# Capture hanya paket UDP
$ sudo tcpdump -i eth0 -nn udp

# Capture hanya paket ICMP (ping)
$ sudo tcpdump -i eth0 -nn icmp

# Capture DNS (UDP port 53)
$ sudo tcpdump -i eth0 -nn udp port 53

# Capture HTTP plaintext
$ sudo tcpdump -i eth0 -nn -A tcp port 80

# Capture HTTPS/TLS (hanya header, payload terenkripsi)
$ sudo tcpdump -i eth0 -nn tcp port 443

# Capture ARP (address resolution protocol)
$ sudo tcpdump -i eth0 -nn arp
💡

Flag -A vs -X: Flag -A menampilkan payload paket dalam format ASCII (berguna untuk HTTP plaintext). Flag -X menampilkan payload dalam format hex + ASCII. Hati-hati — flag ini bisa menampilkan data sensitif seperti password HTTP atau cookie.

4.5 — Capture Incoming/Outgoing Traffic

Direction Filter
# Capture hanya traffic MASUK ke komputer Anda (inbound)
$ sudo tcpdump -i eth0 -nn dst 192.168.1.105

# Capture hanya traffic KELUAR dari komputer Anda (outbound)
$ sudo tcpdump -i eth0 -nn src 192.168.1.105

# Capture seluruh subnet rumah (semua perangkat)
$ sudo tcpdump -i eth0 -nn net 192.168.1.0/24
// 05 — Filter BPF (Berkeley Packet Filter)

Filter BPF — Berkeley Packet Filter

BPF adalah bahasa filter yang digunakan Tcpdump untuk memilih paket yang ingin di-capture. Filter dijalankan di kernel space — sangat efisien karena menyaring paket sebelum masuk ke user space.

Operator Dasar

Operator Fungsi Contoh
host Filter berdasarkan IP (src + dst) host 192.168.1.1
src Filter berdasarkan IP sumber src 192.168.1.100
dst Filter berdasarkan IP tujuan dst 8.8.8.8
port Filter berdasarkan port (src + dst) port 443
src port Filter berdasarkan port sumber src port 80
dst port Filter berdasarkan port tujuan dst port 22
portrange Filter range port portrange 1-1024
net Filter berdasarkan subnet/network net 192.168.1.0/24
tcp / udp / icmp Filter berdasarkan protokol tcp
and / && Kedua kondisi harus terpenuhi host 192.168.1.1 and port 80
or / || Salah satu kondisi terpenuhi port 80 or port 443
not / ! Kebalikan dari kondisi not port 22

Filter Kombinasi Kompleks

Complex BPF Filters
# Traffic HTTP atau HTTPS ke/dari router
$ sudo tcpdump -i eth0 -nn host 192.168.1.1 and (port 80 or port 443)

# TCP traffic KECUALI SSH (exclude port 22)
$ sudo tcpdump -i eth0 -nn tcp and not port 22

# DNS query dari semua perangkat di jaringan rumah
$ sudo tcpdump -i eth0 -nn src net 192.168.1.0/24 and dst port 53

# Traffic antara dua perangkat spesifik
$ sudo tcpdump -i eth0 -nn "(src host 192.168.1.100 and dst host 192.168.1.1) or (src host 192.168.1.1 and dst host 192.168.1.100)"

# Semua broadcast dan multicast (untuk deteksi perangkat IoT)
$ sudo tcpdump -i eth0 -nn broadcast or multicast

# Capture traffic non-SSH dari subnet (monitoring tanpa noise)
$ sudo tcpdump -i eth0 -nn net 192.168.1.0/24 and not port 22

# Deteksi koneksi ke port mencurigakan di luar jaringan lokal
$ sudo tcpdump -i eth0 -nn src net 192.168.1.0/24 and not dst net 192.168.1.0/24 and not dst net 10.0.0.0/8
⚠️

Gunakan tanda kutip untuk filter kompleks: Selalu bungkus filter yang mengandung karakter spesial atau spasi dengan tanda kutip ganda "filter expression" atau gunakan tanda kurung untuk grouping yang benar.

// 06 — Cara Membaca Output Tcpdump

Cara Membaca Output Tcpdump

Setiap baris output Tcpdump berisi informasi lengkap tentang satu paket jaringan. Pelajari cara membaca dan menginterpretasikan setiap bagiannya.

Anatomi Satu Baris Output

Output Anatomy — TCP Packet
┌─ [1] Timestamp — waktu paket diterima │ ┌─ [2] Protokol layer 3 │ │ ┌─ [3] Source IP.Port │ │ │ ┌─ [4] Destination IP.Port │ │ │ │ ┌─ [5] TCP Flags │ │ │ │ │ ┌─ [6] Seq number 14:32:05.123456 IP 192.168.1.105.52341 > 8.8.8.8.443: Flags [S], seq 3842901234, win 64240, options [mss 1460,sackOK,TS val 1234567 ecr 0,nop,wscale 7], length 0
🕐 Timestamp
14:32:05.123456 — Waktu paket diterima dalam format HH:MM:SS.microseconds. Gunakan -tttt untuk format tanggal lengkap.
📍 Source & Destination
192.168.1.105.52341 — format IP.Port. IP address diikuti titik lalu nomor port. Port 52341 = ephemeral port (client).
🚩 TCP Flags
[S] = SYN, [.] = ACK, [S.] = SYN-ACK, [P.] = PSH+ACK (data), [F.] = FIN, [R] = RST (reset/reject), [U] = URG
🔢 Sequence & ACK Number
seq 3842901234 — nomor urut paket TCP. ack 12345 — konfirmasi paket yang sudah diterima. Berguna untuk analisis retransmit.
📏 Length & Win
length 0 = panjang payload data (SYN tidak punya data). win 64240 = TCP window size (buffer receiver).
⏱️ TTL
Tampil saat pakai flag -v: ttl 64 — Time To Live. Setiap router mengurangi 1. TTL=64 biasanya Linux, TTL=128 Windows, TTL=255 router.

Membaca Berbagai Jenis Paket

DNS Query & Response
┌─ DNS Query (client bertanya ke DNS server) 14:32:05.001 IP 192.168.1.105.34521 > 8.8.8.8.53: 24351+ A? google.com. (28) │ A? = query type A record (IPv4 address) │ google.com. = domain yang ditanyakan │ (28) = panjang paket DNS
┌─ DNS Response (server menjawab) 14:32:05.045 IP 8.8.8.8.53 > 192.168.1.105.34521: 24351 1/0/0 A 142.250.4.100 (44) │ 1/0/0 = 1 answer, 0 authority, 0 additional │ A 142.250.4.100 = IP address hasil resolve
TCP 3-Way Handshake
┌─ [1] SYN — client memulai koneksi 14:32:06.100 IP 192.168.1.105.54321 > 93.184.216.34.80: Flags [S], seq 1234567890, win 64240, length 0 ┌─ [2] SYN-ACK — server setuju 14:32:06.150 IP 93.184.216.34.80 > 192.168.1.105.54321: Flags [S.], seq 9876543210, ack 1234567891, win 65535, length 0 ┌─ [3] ACK — client konfirmasi 14:32:06.151 IP 192.168.1.105.54321 > 93.184.216.34.80: Flags [.], ack 9876543211, win 502, length 0 ┌─ [4] HTTP GET — data dikirim 14:32:06.152 IP 192.168.1.105.54321 > 93.184.216.34.80: Flags [P.], seq 1:78, ack 1, win 502, length 77
ARP — Address Resolution Protocol
┌─ ARP Request — siapa yang punya 192.168.1.1? 14:32:07.000 ARP, Request who-has 192.168.1.1 tell 192.168.1.105, length 28 ┌─ ARP Reply — saya! ini MAC address saya 14:32:07.001 ARP, Reply 192.168.1.1 is-at a8:7e:ea:c1:45:2f, length 28 │ ARP berlebihan bisa indikasi ARP spoofing atau banyak perangkat baru
ICMP — Ping
┌─ ICMP Echo Request (ping out) 14:32:08.000 IP 192.168.1.105 > 8.8.8.8: ICMP echo request, id 12345, seq 1, length 64 ┌─ ICMP Echo Reply (pong back) 14:32:08.022 IP 8.8.8.8 > 192.168.1.105: ICMP echo reply, id 12345, seq 1, length 64
TLS Handshake (HTTPS)
# Capture dengan flag -v untuk lihat TLS info
$ sudo tcpdump -i eth0 -nn -v tcp port 443

14:32:10.100 IP 192.168.1.105.55123 > 93.184.216.34.443: Flags [P.], length 318 TLS 1.3, Handshake, ClientHello (1) Version: TLS 1.0 (compatibility) Random: 5f3a2b1c... Server Name: www.example.com │ SNI (Server Name Indication) terlihat di ClientHello — bisa identifikasi situs yang dikunjungi │ Namun payload (data) terenkripsi — tidak bisa dibaca isinya
// 07 — Simpan & Baca File PCAP

Menyimpan & Membaca File PCAP

Simpan hasil capture ke file .pcap untuk analisis mendalam, perbandingan historis, atau dibuka di Wireshark.

Menyimpan Capture ke File

Write PCAP File
# Simpan capture ke file .pcap (-w = write)
$ sudo tcpdump -i eth0 -nn -w capture.pcap tcpdump: listening on eth0, link-type EN10MB, snapshot length 262144 bytes ^C 247 packets captured
# Simpan dengan nama file berisi timestamp otomatis
$ sudo tcpdump -i eth0 -nn -w capture_$(date +%Y%m%d_%H%M%S).pcap

# Simpan hanya traffic DNS ke file
$ sudo tcpdump -i eth0 -nn port 53 -w dns_capture.pcap

# Rotate file setiap 100MB (file baru otomatis dibuat)
$ sudo tcpdump -i eth0 -nn -C 100 -w capture.pcap

# Rotate file setiap 60 detik
$ sudo tcpdump -i eth0 -nn -G 60 -w capture_%Y%m%d_%H%M%S.pcap

# Batasi jumlah file rotate (max 10 file, lalu overwrite yang lama)
$ sudo tcpdump -i eth0 -nn -G 60 -W 10 -w capture_%Y%m%d_%H%M%S.pcap

Membaca File PCAP

Read PCAP File
# Baca file pcap (-r = read)
$ sudo tcpdump -r capture.pcap -nn

# Baca dan filter hanya DNS dari file
$ sudo tcpdump -r capture.pcap -nn port 53

# Baca dengan detail verbose
$ sudo tcpdump -r capture.pcap -nn -vvv

# Buka di Wireshark (GUI)
$ wireshark capture.pcap

# Analisis dengan tshark (CLI Wireshark)
$ tshark -r capture.pcap -Y "dns" -T fields -e dns.qry.name
Flag Fungsi
-w file.pcap Tulis capture ke file PCAP. File disimpan dalam format libpcap.
-r file.pcap Baca file PCAP yang sudah tersimpan. Bisa difilter ulang saat dibaca.
-C 100 Rotate file setiap 100 MB. Nama file auto diberi nomor urut.
-G 60 Rotate file setiap 60 detik. Gunakan format strftime di nama file.
-W 10 Maksimal 10 file rotate — setelah penuh, file lama di-overwrite.
-s 0 Capture full packet (snaplen = 0 = unlimited). Default 262144 bytes.
-S Print absolute sequence numbers (bukan relative) untuk analisis TCP.
💡

Snaplen (-s): Default Tcpdump modern sudah 262144 bytes (full packet). Jika menggunakan versi lama, gunakan -s 0 untuk memastikan seluruh payload paket tersimpan, bukan hanya headernya saja.

// 08 — Use Cases Legal & Aman

Use Cases Legal & Aman

🏠 Troubleshooting Jaringan Rumah

Network Troubleshooting
# Cek apakah koneksi ke router berhasil (ping + ARP)
$ sudo tcpdump -i eth0 -nn host 192.168.1.1 and (arp or icmp) -c 20

# Debugging koneksi lambat — cek retransmit TCP
$ sudo tcpdump -i eth0 -nn tcp -w troubleshoot.pcap -c 500
# Buka di Wireshark, filter: tcp.analysis.retransmission

# Analisis latency DNS — cek berapa lama DNS resolve
$ sudo tcpdump -i eth0 -nn -tttt port 53 -c 30 2024-11-20 14:32:05.001234 IP 192.168.1.105.34521 > 8.8.8.8.53: A? google.com 2024-11-20 14:32:05.045678 IP 8.8.8.8.53 > 192.168.1.105.34521: A 142.250.4.100 │ Latency DNS = 45678 - 1234 = 44.4ms — masih wajar (<100ms)

📱 Mendeteksi Perangkat IoT Aktif

IoT Device Detection
# Monitor semua broadcast — perangkat IoT sering kirim broadcast
$ sudo tcpdump -i eth0 -nn -e broadcast 14:32:00 a8:7e:ea:c1:45:2f > ff:ff:ff:ff:ff:ff, ARP who-has 192.168.1.100 14:32:01 b4:e6:2d:00:11:22 > ff:ff:ff:ff:ff:ff, ARP who-has 192.168.1.105
# Monitor traffic MQTT (port 1883) — protokol IoT umum
$ sudo tcpdump -i eth0 -nn port 1883 or port 8883

# Lihat siapa yang melakukan koneksi ke internet
$ sudo tcpdump -i eth0 -nn "src net 192.168.1.0/24 and not dst net 192.168.1.0/24" -c 50

🔍 Debugging DNS

DNS Debug
# Monitor semua DNS query dan response dari semua perangkat
$ sudo tcpdump -i eth0 -nn port 53 IP 192.168.1.105 > 8.8.8.8: A? youtube.com IP 192.168.1.101 > 8.8.8.8: A? doubleclick.net IP 192.168.1.102 > 8.8.8.8: A? analytics.google.com
# Cek DNS leak — apakah DNS melewati router lokal atau langsung ke internet?
$ sudo tcpdump -i eth0 -nn "dst port 53 and not dst host 192.168.1.1" # Jika ada output, ada DNS yang bypass router — bisa jadi DNS leak

📊 Monitoring Inventory Service Jaringan

Service Inventory
# Lihat semua port yang diakses di jaringan rumah (5 menit)
$ sudo tcpdump -i eth0 -nn -w inventory.pcap
# Setelah selesai, analisis port unik yang muncul:
$ sudo tcpdump -r inventory.pcap -nn | awk '{print $5}' | grep -oP '\d+$' | sort -n | uniq -c | sort -rn | head -20

# Deteksi broadcast berlebihan (broadcast storm indicator)
$ sudo tcpdump -i eth0 -nn broadcast -c 100 | wc -l # Jika 100 paket datang sangat cepat, mungkin ada broadcast storm
// 09 — Defensive Monitoring

Penggunaan Defensif — Security Monitoring

Tcpdump sangat berguna untuk monitoring keamanan jaringan rumah secara defensif — mendeteksi anomali, koneksi mencurigakan, dan traffic tidak terenkripsi.

🔍 Deteksi Port Scanning Internal

Internal Scan Detection
# Deteksi banyak SYN ke berbagai port dari satu IP (ciri port scan)
$ sudo tcpdump -i eth0 -nn "tcp[tcpflags] == tcp-syn" # Jika satu IP mengirim banyak SYN ke berbagai port dalam waktu singkat = scan
14:35:01 IP 192.168.1.200.40001 > 192.168.1.105.22: Flags [S] 14:35:01 IP 192.168.1.200.40002 > 192.168.1.105.23: Flags [S] 14:35:01 IP 192.168.1.200.40003 > 192.168.1.105.25: Flags [S] 14:35:01 IP 192.168.1.200.40004 > 192.168.1.105.80: Flags [S] ⚠ Pola ini menunjukkan ada perangkat di 192.168.1.200 sedang scanning port Anda!

🚨 Deteksi Koneksi Mencurigakan

Suspicious Connection Detection
# Monitor koneksi ke port yang tidak biasa dari jaringan lokal
$ sudo tcpdump -i eth0 -nn "src net 192.168.1.0/24 and dst port not (80 or 443 or 53 or 22)"

# Deteksi ARP spoofing — banyak ARP reply dari satu MAC ke berbagai IP
$ sudo tcpdump -i eth0 -nn arp ARP, Reply 192.168.1.1 is-at aa:bb:cc:11:22:33 ARP, Reply 192.168.1.105 is-at aa:bb:cc:11:22:33 ⚠ MAC yang sama mengklaim beberapa IP = kemungkinan ARP spoofing!
# Monitor koneksi outbound mencurigakan (ke port non-standard)
$ sudo tcpdump -i eth0 -nn "src host 192.168.1.105 and dst port not (80 or 443 or 53 or 22 or 25 or 143 or 993 or 465)"

🔓 Deteksi Traffic Tidak Terenkripsi

Plaintext Traffic Detection
# Lihat konten HTTP plaintext (-A = ASCII output)
$ sudo tcpdump -i eth0 -nn -A port 80 -c 20 GET /login HTTP/1.1 Host: example.com Content-Type: application/x-www-form-urlencoded username=admin&password=password123 │ ⚠ Password terlihat jelas di HTTP plaintext! Selalu gunakan HTTPS!
# Cek apakah ada Telnet (tidak terenkripsi) aktif di jaringan
$ sudo tcpdump -i eth0 -nn port 23 -c 10 # Jika ada traffic Telnet = bahaya, beralih ke SSH!
# Cek FTP login plaintext
$ sudo tcpdump -i eth0 -nn -A port 21
🚫

Penting: Flag -A dan -X bisa menampilkan data sensitif termasuk password, cookie, dan token. Hanya gunakan di jaringan yang sepenuhnya Anda miliki. Menyimpan data seperti ini dari jaringan orang lain adalah tindakan ilegal penyadapan.

// 10 — Etika & Risiko Penggunaan

Etika & Risiko Penggunaan Tcpdump

🚫

ILEGAL — JANGAN LAKUKAN: Menjalankan Tcpdump di jaringan atau perangkat yang bukan milik Anda tanpa izin eksplisit adalah penyadapan ilegal di Indonesia (UU ITE No. 19 Tahun 2016 Pasal 31) dan bisa dikenakan pidana penjara dan denda besar. Packet sniffing di jaringan publik juga melanggar hukum.

✅ BOLEH dilakukan
  • Capture di jaringan rumah milik sendiri
  • Capture di lab virtual machine milik sendiri
  • Capture di perangkat dengan izin tertulis
  • Capture untuk debugging layanan sendiri
  • Platform legal: TryHackMe, HackTheBox
❌ TIDAK BOLEH dilakukan
  • Capture di WiFi publik/cafe tanpa izin
  • Sniffing jaringan kantor/sekolah tanpa otorisasi
  • Capture data orang lain (credentials, data pribadi)
  • Menyimpan dan menggunakan data yang di-capture dari jaringan orang lain
  • Capture di VPN shared tanpa izin provider

Risiko Privasi Data

🔑 Credential Exposure
HTTP, FTP, Telnet, POP3 tanpa enkripsi mengirim password dalam plaintext. Tcpdump dengan -A bisa menangkap ini. Selalu gunakan HTTPS/SFTP/SSH.
🍪 Session Cookie
Cookie session HTTP bisa di-capture dan digunakan untuk session hijacking. Ini alasan cookie harus memiliki flag Secure dan HttpOnly.
📧 Email Plaintext
POP3 (110) dan IMAP (143) tanpa TLS mengirim email dan password dalam plaintext. Gunakan port 993 (IMAPS) atau 995 (POP3S).
// 11 — Best Practice

Best Practice — Capture yang Aman & Efisien

Prinsip Capture yang Baik

🎯 Selalu Gunakan Filter
Jangan capture semua traffic tanpa filter di jaringan sibuk. Filter BPF diproses di kernel — efisien dan tidak membuang resource. Spesifik ke host/port yang dibutuhkan.
⏱️ Batasi Durasi
Gunakan -c N (jumlah paket) atau buat script dengan timeout. Jangan biarkan capture berjalan selamanya — file .pcap bisa sangat besar.
💾 Rotate File
Gunakan -C (size) atau -G (time) untuk rotate otomatis. Kombinasikan dengan -W untuk limit jumlah file agar disk tidak penuh.
🔐 Amankan File PCAP
File .pcap berisi data sensitif. Simpan di direktori terbatas (chmod 600), jangan taruh di folder publik, dan hapus setelah analisis selesai.
🌐 Pilih Interface Tepat
Gunakan interface spesifik, bukan any. Interface any tidak support promiscuous mode dan bisa duplikat paket di beberapa distro.
📝 Dokumentasikan
Selalu catat: tanggal, tujuan capture, interface, filter yang digunakan. File pcap tanpa konteks tidak berguna untuk analisis di kemudian hari.
Best Practice Commands
# ✅ BAIK: Filter spesifik, batasi paket, no DNS lookup
$ sudo tcpdump -i eth0 -nn -c 200 port 53

# ✅ BAIK: Simpan ke file dengan rotate dan limit
$ sudo tcpdump -i eth0 -nn -G 300 -W 6 -w /tmp/cap_%Y%m%d_%H%M%S.pcap

# ✅ BAIK: Capture background dengan nohup, stop dengan kill
$ sudo nohup tcpdump -i eth0 -nn -w capture.pcap port 80 & [1] 12345 $ sudo kill 12345

# ❌ HINDARI: Capture semua traffic tanpa filter tanpa batas
# sudo tcpdump -i eth0 -A <-- bisa capture data sensitif semua orang!

# ❌ HINDARI: Simpan ke disk tanpa limit ukuran
# sudo tcpdump -i eth0 -w bigfile.pcap <-- bisa isi seluruh disk!

// 13 — Mini Latihan Praktik Bertahap

Mini Latihan Praktik Bertahap

1
Kenali Jaringan & Interface
Beginner

Tujuan: Memahami interface jaringan dan melakukan capture pertama.

1
Jalankan sudo tcpdump -D — catat nama interface yang tersedia (eth0, wlan0, dll).
2
Jalankan ip addr show untuk mengetahui IP address dan subnet Anda.
3
Capture 20 paket: sudo tcpdump -i eth0 -nn -c 20 — amati output.
4
Identifikasi: IP address, port, protokol apa yang muncul paling sering?
5
Capture hanya ARP: sudo tcpdump -i eth0 -nn -e arp — lihat MAC address perangkat di jaringan.
🎯
Sukses jika Anda bisa mengidentifikasi nama interface, IP Anda, gateway, dan minimal 3 jenis protokol dalam capture.
2
Debug DNS & Analisis Latency
Beginner

Tujuan: Memahami bagaimana DNS bekerja dan menganalisis latency resolusi.

1
Jalankan di terminal 1: sudo tcpdump -i eth0 -nn -tttt port 53
2
Di terminal 2, jalankan: ping google.com atau buka browser.
3
Amati output Tcpdump — cari pasangan query (A? domain.com) dan response (A IP).
4
Hitung latency DNS: selisih timestamp query vs response. Normal < 100ms.
5
Cek apakah ada query ke selain router Anda (DNS leak): sudo tcpdump -i eth0 -nn "dst port 53 and not dst host 192.168.1.1"
🎯
Sukses jika Anda bisa membaca pasangan DNS query-response dan mengukur latency DNS Anda.
3
Monitor Traffic HTTP vs HTTPS
Beginner

Tujuan: Memahami perbedaan HTTP (plaintext) dan HTTPS (terenkripsi).

1
Capture HTTP dengan payload: sudo tcpdump -i eth0 -nn -A port 80 -c 30
2
Di browser, kunjungi situs HTTP (bukan HTTPS) — amati GET request yang terlihat di terminal.
3
Sekarang capture HTTPS: sudo tcpdump -i eth0 -nn -A port 443 -c 30
4
Kunjungi situs HTTPS — amati bahwa payload hanya terlihat sebagai data acak terenkripsi.
5
Perhatikan: pada TLS handshake, SNI (Server Name) masih terlihat di ClientHello meski data terenkripsi.
🎯
Sukses jika Anda bisa melihat perbedaan jelas antara konten HTTP yang terbaca dan HTTPS yang terenkripsi.
4
Deteksi Perangkat & Monitoring IoT
Intermediate

Tujuan: Menggunakan Tcpdump untuk memetakan aktivitas perangkat di jaringan rumah.

1
Monitor broadcast 2 menit: sudo tcpdump -i eth0 -nn -e broadcast -c 100 -w iot_scan.pcap
2
Baca hasilnya dan ekstrak MAC address unik: tcpdump -r iot_scan.pcap -nn -e | awk '{print $2}' | sort -u
3
Identifikasi vendor dari MAC address menggunakan macvendors.com (masukkan 3 byte pertama).
4
Monitor MQTT: sudo tcpdump -i eth0 -nn port 1883 -c 20 — apakah ada perangkat IoT MQTT?
5
Buat daftar perangkat: IP, MAC, vendor, protokol aktif. Identifikasi perangkat tak dikenal.
🎯
Sukses jika Anda bisa membuat inventori perangkat jaringan berdasarkan traffic yang di-capture.
5
Capture & Analisis dengan Wireshark
Intermediate

Tujuan: Gunakan Tcpdump untuk capture, lalu analisis mendalam di Wireshark.

1
Capture 60 detik traffic umum: sudo tcpdump -i eth0 -nn -w full_capture.pcap, lalu buka browser normal selama 60 detik.
2
Buka di Wireshark: wireshark full_capture.pcap
3
Di Wireshark, gunakan filter: dns — lihat semua DNS query. Domain apa yang paling sering diakses?
4
Filter: tcp.flags.syn==1 and tcp.flags.ack==0 — lihat semua connection initiation.
5
Menu Statistics → Conversations → TCP — lihat top talkers di jaringan Anda.
6
Menu Statistics → Protocol Hierarchy — lihat distribusi protokol dalam capture.
🎯
Sukses jika Anda bisa membuat laporan: top 5 domain yang diakses, top 3 protokol, dan identifikasi satu koneksi lengkap TCP dari SYN sampai FIN.
6
Defensive Security Monitoring
Intermediate

Tujuan: Setup monitoring defensif sederhana untuk keamanan jaringan rumah.

1
Monitor SYN flood/scan: sudo tcpdump -i eth0 -nn "tcp[tcpflags]==tcp-syn" -c 50 -w syn_monitor.pcap
2
Cek traffic plaintext berbahaya: sudo tcpdump -i eth0 -nn port 23 or port 21 or port 110 -c 20 — apakah ada Telnet/FTP/POP3?
3
Deteksi koneksi ke luar yang tidak biasa: sudo tcpdump -i eth0 -nn "src net 192.168.1.0/24 and dst port not (80 or 443 or 53 or 22)" -c 30
4
Monitor ARP untuk deteksi perangkat baru: sudo tcpdump -i eth0 -nn arp -c 30 — catat semua MAC address.
5
Buat script monitoring sederhana yang jalankan Tcpdump setiap malam dan simpan ke file dengan rotasi 7 hari.
6
Dokumentasikan baseline: traffic normal Anda seperti apa? DNS server mana yang digunakan? Port apa yang biasa terbuka?
🎯
Sukses jika Anda memiliki pemahaman tentang baseline traffic normal jaringan rumah dan bisa mendeteksi anomali dari baseline tersebut.
🎓

Langkah Selanjutnya: Setelah menguasai Tcpdump, pelajari Wireshark untuk analisis visual, tshark untuk scripting, dan Zeek (Bro) untuk analisis traffic otomatis dan deteksi ancaman.

// 14 — Integrasi dengan Tools Lain

Integrasi Tcpdump dengan Tools Lain

Tcpdump menjadi jauh lebih powerful ketika dikombinasikan dengan tools analisis lainnya. Berikut cara mengintegrasikan Tcpdump dengan ekosistem tools jaringan dan keamanan.

🦈 Wireshark — GUI Analyzer
Tool GUI paling populer untuk analisis packet. Buka file .pcap dari Tcpdump, filter visual, rekonstruksi stream TCP, statistik lengkap, dan decode ratusan protokol secara otomatis.
🔬 tshark — CLI Wireshark
Versi command-line dari Wireshark. Sangat berguna untuk scripting, automasi analisis, dan extract field spesifik dari pcap. Decode protokol lebih banyak dari Tcpdump.
🦓 Zeek (Bro) — Traffic Analyzer
Framework analisis traffic jaringan level tinggi. Zeek menghasilkan log terstruktur (conn.log, dns.log, http.log) dari pcap. Sangat berguna untuk threat hunting dan security monitoring.
🛡️ Suricata / Snort — IDS/IPS
IDS/IPS yang bisa membaca file pcap dari Tcpdump dan menjalankan rules deteksi ancaman. Tcpdump capture → Suricata analyze → alert jika ada pattern berbahaya.

Integrasi Tcpdump + Wireshark

Tcpdump → Wireshark Workflow
# 1. Capture dengan Tcpdump di server/CLI (tanpa GUI)
$ sudo tcpdump -i eth0 -nn -w capture.pcap port 80 or port 443

# 2. Transfer file pcap ke komputer lokal (jika dari remote server)
$ scp user@192.168.1.100:capture.pcap ./

# 3. Buka langsung di Wireshark
$ wireshark capture.pcap

# 4. Alternatif: pipe langsung ke Wireshark real-time (remote capture)
$ ssh user@192.168.1.100 "sudo tcpdump -i eth0 -nn -U -w -" | wireshark -k -i - │ -U = packet-buffered (langsung kirim, tidak buffer dulu) │ -w - = write ke stdout │ Wireshark -k = mulai capture langsung │ Wireshark -i - = baca dari stdin

Integrasi Tcpdump + tshark

tshark Analysis Commands
# Install tshark
$ sudo apt install tshark

# Extract semua domain DNS yang diquery dari pcap
$ tshark -r capture.pcap -Y "dns.flags.response == 0" -T fields -e dns.qry.name | sort | uniq -c | sort -rn 47 google.com 23 youtube.com 18 doubleclick.net
# Lihat semua HTTP request (method + URL) dari pcap
$ tshark -r capture.pcap -Y "http.request" -T fields -e http.request.method -e http.host -e http.request.uri

# Statistik koneksi: source IP, destination IP, bytes transferred
$ tshark -r capture.pcap -q -z conv,tcp

# Filter dan export ke file baru
$ tshark -r capture.pcap -Y "ip.addr == 8.8.8.8" -w filtered.pcap

Integrasi Tcpdump + Zeek

Zeek Analysis from PCAP
# Install Zeek
$ sudo apt install zeek

# Analisis pcap dengan Zeek — menghasilkan log terstruktur
$ zeek -r capture.pcap Zeek menghasilkan file log: conn.log — semua koneksi TCP/UDP (IP, port, durasi, bytes) dns.log — semua DNS query dan response http.log — semua HTTP request (method, host, URI, response code) ssl.log — semua TLS/SSL connection (server name, cert) files.log — semua file yang ditransfer
# Baca conn.log dengan format tabel
$ cat conn.log | zeek-cut id.orig_h id.resp_h id.resp_p proto duration | head -20

# Cari semua domain unik dari dns.log
$ cat dns.log | zeek-cut query | sort -u

Integrasi dengan IDS — Suricata

Suricata PCAP Analysis
# Capture dengan Tcpdump dulu
$ sudo tcpdump -i eth0 -nn -w suspicious_traffic.pcap -c 1000

# Analisis pcap dengan Suricata dan rules ETOpen
$ sudo suricata -r suspicious_traffic.pcap -l ./logs/ Reading file 'suspicious_traffic.pcap' 28/11/2024-14:32:05 [**] [1:2001219:20] ET SCAN Potential SSH Scan [**] 28/11/2024-14:32:10 [**] [1:2013504:5] ET POLICY DNS Query for TOR .onion [**] │ Suricata mencocokkan traffic dengan rules IDS │ Alert muncul jika ada pola yang mencurigakan
💡

Workflow Lengkap: Capture dengan Tcpdump → Simpan .pcap → Analisis dengan Wireshark (visual) + tshark (scripting) + Zeek (log terstruktur) + Suricata (threat detection). Setiap tool melengkapi satu sama lain.

// 15 — Perbandingan Konsep Penting

Perbandingan Konsep Penting

Tcpdump vs Wireshark

Aspek Tcpdump Wireshark
Interface Command-line (CLI) Graphical UI (GUI)
Instalasi Ringan, tersedia di semua Linux Butuh desktop environment, lebih besar
Remote Server ✅ Sangat ideal untuk server headless ❌ Butuh GUI atau X forwarding
Scripting ✅ Mudah dikombinasikan dengan shell/script ⚠️ Terbatas (gunakan tshark)
Analisis Visual ❌ Teks saja ✅ Warna, diagram, statistik visual
Protocol Decode Terbatas (protokol umum) ✅ 3000+ protokol didukung
Real-time Follow ❌ Tidak bisa follow stream GUI ✅ Follow TCP/UDP stream, reassemble
Resource Usage Sangat ringan Berat (RAM tinggi untuk file besar)
Library libpcap libpcap + winpcap/npcap
Format File .pcap (standard) .pcapng (extended), kompatibel pcap
Best For Capture, quick filter, scripting Analisis mendalam, debugging protokol

Packet Capture vs Port Scanning

Aspek Packet Capture (Tcpdump) Port Scanning (Nmap)
Mode Operasi Pasif — hanya mendengarkan Aktif — mengirim paket probe
Deteksi Tidak terdeteksi oleh target Terlihat di log dan IDS target
Tujuan Analisis traffic yang sudah ada Discovery host dan port terbuka
Pengaruh Jaringan Tidak ada (hanya read) Menghasilkan traffic tambahan
Informasi Siapa berbicara dengan siapa, kapan, apa Host aktif, port terbuka, service, OS
Risiko Legal Aman jika di jaringan sendiri Aman jika di jaringan sendiri
Gunakan Untuk Monitoring, troubleshooting, forensik Inventory jaringan, security audit

Passive Monitoring vs Active Scanning

👂 Passive Monitoring
  • Tools: Tcpdump, Wireshark, Zeek, ntopng
  • Tidak mengirim paket — hanya observe
  • Tidak terdeteksi oleh perangkat lain
  • Hanya bisa melihat traffic yang melewati interface
  • Ideal untuk monitoring kontinyu dan forensik
  • Tidak bisa menemukan host yang tidak mengirim traffic
📡 Active Scanning
  • Tools: Nmap, Masscan, Netcat, Ping
  • Mengirim paket ke target — generate traffic
  • Terlihat di log firewall dan IDS
  • Bisa menemukan host yang diam sekalipun
  • Ideal untuk asset discovery dan security audit
  • Bisa memicu alert atau crash perangkat sensitif
🧠

Mindset Defensif: Seorang network defender yang baik memahami kedua teknik — passive monitoring untuk baseline dan anomaly detection, active scanning untuk asset inventory berkala. Kombinasi keduanya memberikan visibilitas jaringan yang komprehensif.

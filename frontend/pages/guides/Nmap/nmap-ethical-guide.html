// 01 — Apa itu Nmap?

Apa itu Nmap?

Nmap (Network Mapper) adalah tool open-source untuk eksplorasi jaringan dan audit keamanan. Diciptakan oleh Gordon Lyon (Fyodor) pada 1997, Nmap digunakan oleh admin jaringan, pentester, dan profesional keamanan di seluruh dunia untuk:

🔍 Host Discovery
Menemukan perangkat aktif (komputer, printer, router, kamera, IoT) di jaringan.
🚪 Port Scanning
Mendeteksi port yang terbuka, tertutup, atau difilter pada setiap perangkat.
🏷️ Service Detection
Mengidentifikasi service (HTTP, SSH, FTP) dan versinya yang berjalan di port tertentu.
💻 OS Detection
Menebak sistem operasi target berdasarkan karakteristik respon jaringan (fingerprinting).
📜 NSE Scripting
Menjalankan skrip Lua untuk deteksi kerentanan, enumerasi service, dan audit konfigurasi.
📊 Network Inventory
Membuat inventaris perangkat di jaringan — berguna untuk audit dan dokumentasi.
ℹ️

Konteks Penggunaan Legal: Nmap adalah tool yang sah dan banyak dipakai oleh sysadmin. Tool ini bahkan muncul dalam film Hollywood seperti The Matrix. Yang menentukan legalitasnya adalah siapa yang menjadi target scan, bukan toolnya sendiri.

// 02 — Instalasi Nmap

Instalasi Nmap

🐧 Linux (Debian / Ubuntu)

Terminal — Linux
# Update daftar package terlebih dahulu
$ sudo apt update
# Install Nmap $ sudo apt install -y nmap
# Verifikasi instalasi
$ nmap --version Nmap version 7.94 ( https://nmap.org ) Platform: x86_64-pc-linux-gnu

🐧 Linux (Arch / Manjaro)

Terminal — Arch
$ sudo pacman -S nmap

🪟 Windows

Download installer dari nmap.org/download.html — pilih file .exe (Windows Self-installer). Installer sudah menyertakan Zenmap (GUI Nmap) dan Npcap (packet capture driver).

Command Prompt / PowerShell
# Jalankan sebagai Administrator, lalu verifikasi: C:\> nmap --version # Atau menggunakan Winget (Windows 11) C:\> winget install nmap

🍎 macOS

Terminal — macOS
# Menggunakan Homebrew (rekomendasi)
$ brew install nmap # Verifikasi $ nmap --version
⚠️

Linux & macOS: Banyak perintah Nmap memerlukan hak akses root/sudo untuk raw socket. Jika tanpa sudo, fitur seperti OS detection dan SYN scan tidak akan berjalan dengan benar.

// 03 — Mengetahui IP Gateway & Subnet

Mengetahui IP Gateway & Subnet

Sebelum scanning, Anda perlu mengetahui IP Anda sendiri, gateway (router), dan subnet jaringan.

🐧 Linux

Terminal — Linux
# Lihat semua interface dan IP
$ ip addr show 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> inet 192.168.1.105/24 brd 192.168.1.255 scope global eth0 # Lihat gateway (router)
$ ip route show default via 192.168.1.1 dev eth0 proto dhcp 192.168.1.0/24 dev eth0 proto kernel scope link # Alternatif: ifconfig (install net-tools dulu)
$ ifconfig

🪟 Windows

Command Prompt
C:\> ipconfig Windows IP Configuration Ethernet adapter Local Area Connection: IPv4 Address. . . . . : 192.168.1.105 Subnet Mask . . . . . : 255.255.255.0 Default Gateway . . . : 192.168.1.1

🍎 macOS

Terminal — macOS
$ ifconfig en0 inet 192.168.1.105 netmask 0xffffff00 broadcast 192.168.1.255
$ netstat -nr | grep default default 192.168.1.1 UGSc en0
💡

Notasi CIDR: 192.168.1.0/24 artinya jaringan dengan 256 alamat IP (192.168.1.0 s/d 192.168.1.255). /24 adalah subnet mask 255.255.255.0. Ini adalah subnet paling umum di jaringan rumah.

// 05 — Teknik Scan Utama

Teknik Scan Utama

5.1 — Ping Scan

Digunakan untuk verifikasi apakah host aktif tanpa membuka koneksi port.

Ping Scan
$ nmap -sn 192.168.1.1
# Cek satu host spesifik (gateway/router) $ nmap -sn 192.168.1.1-50
# Cek range IP tertentu (1 sampai 50)
✅

Kapan digunakan: Quick check apakah perangkat menyala. Sangat aman, tidak meninggalkan jejak signifikan di log. Risiko: Sangat rendah.

5.2 — Port Scan Dasar (TCP SYN Scan)

TCP SYN Scan — Default
# Scan 1000 port paling umum di router
$ sudo nmap -sS 192.168.1.1 # Scan port tertentu
$ sudo nmap -sS -p 22,80,443,8080 192.168.1.1
# Scan semua 65535 port (lambat) $ sudo nmap -sS -p- 192.168.1.1 # Scan tanpa root (TCP Connect - lebih lambat) $ nmap -sT 192.168.1.1
Flag Nama Keterangan Butuh Root?
-sS SYN Scan (Stealth) Kirim paket SYN, tidak selesaikan handshake. Lebih cepat dan lebih sedikit log di target. Ya (sudo)
-sT TCP Connect Scan Lakukan full TCP handshake. Lebih lambat, lebih terlihat di log, tapi tidak butuh root. Tidak
-p 80,443 Port Spesifik Hanya scan port yang disebutkan. Gunakan koma untuk beberapa port. —
-p- All Ports Scan semua 65535 port. Sangat lambat, gunakan hanya bila perlu. —

5.3 — Service & Version Detection

Service Version Detection
# Deteksi service dan versinya
$ sudo nmap -sV 192.168.1.1
# Intensitas deteksi: 0 (ringan) hingga 9 (agresif)
$ sudo nmap -sV --version-intensity 5 192.168.1.1
PORT STATE SERVICE VERSION 80/tcp open http Apache httpd 2.4.54 ((Debian)) 443/tcp open https OpenSSL/3.0.2 22/tcp open ssh OpenSSH 8.9p1 Ubuntu
Flag Keterangan
-sV Aktifkan version detection. Nmap akan probe setiap port terbuka untuk mengidentifikasi service dan versinya.
--version-intensity [0-9] Level 0 = hanya probe dasar (cepat). Level 9 = probe intensif (lambat tapi lebih akurat).

5.4 — OS Detection

OS Fingerprinting
# Deteksi OS target (butuh root)
$ sudo nmap -O 192.168.1.1
OS detection performed. Please report any incorrect results. Nmap scan report for 192.168.1.1 OS details: Linux 4.15 - 5.8 Network Distance: 1 hop OS CPE: cpe:/o:linux:linux_kernel:4 # Kombinasi: OS + Service detection (paling umum dipakai) $ sudo nmap -sV -O 192.168.1.100
⚠️

Akurasi OS Detection: Tidak selalu 100% akurat. Router dan embedded device sering memberikan hasil yang kurang tepat. Gunakan sebagai petunjuk awal, bukan kesimpulan mutlak.

5.5 — UDP Scan Dasar

UDP Scan
# Scan UDP port penting (sangat lambat, bisa makan waktu lama)
$ sudo nmap -sU -p 53,67,68,123,161 192.168.1.1
# Port UDP penting yang perlu dicek:
# 53 = DNS
# 67 = DHCP Server
# 123 = NTP (sinkronisasi waktu)
# 161 = SNMP (manajemen jaringan)
# 500 = IPSec VPN PORT STATE SERVICE 53/udp open domain 67/udp open|filtered dhcps 161/udp open snmp
⚠️

UDP Scan sangat lambat karena tidak ada ACK seperti TCP. Selalu batasi jumlah port saat scan UDP. Hindari -sU tanpa filter port di seluruh subnet — bisa memakan waktu berjam-jam.

5.6 — Scan Seluruh Subnet Rumah

Subnet Scan Komprehensif
# Scan seluruh subnet: temukan host + scan top 1000 port
$ sudo nmap -sV -O --top-ports 100 192.168.1.0/24
# Scan lebih ringan: hanya temukan host aktif + service dasar
$ sudo nmap -sn 192.168.1.0/24
# Scan dengan output ke file (untuk dokumentasi)
$ sudo nmap -sV -oN hasil_scan.txt 192.168.1.0/24
# Scan jaringan 10.0.0.x (subnet alternatif) $ sudo nmap -sn 10.0.0.0/24
Flag Keterangan
--top-ports 100 Hanya scan 100 port yang paling sering digunakan. Lebih cepat dari scan default 1000 port.
-oN file.txt Simpan output dalam format teks normal (human-readable). Bagus untuk dokumentasi dan audit.
-oX file.xml Output format XML — bisa diimport ke tool lain seperti Metasploit atau dibuka di browser.
-oG file.gnmap Output format "grepable" — mudah diproses dengan grep, awk, dsb.
// 06 — Interpretasi Hasil Scan

Interpretasi Hasil Scan

Status Port

OPEN

Aplikasi aktif mendengarkan di port ini. Koneksi bisa diterima. Artinya ada service yang berjalan dan bisa diakses. Perlu diaudit apakah service ini memang diperlukan.

CLOSED

Port dapat diakses, tapi tidak ada aplikasi yang mendengarkan. Host aktif dan merespon, tapi service tidak berjalan di port ini. Aman, tapi perlu diperhatikan jika tidak terduga.

FILTERED

Nmap tidak bisa menentukan apakah port terbuka atau tertutup — kemungkinan diblokir oleh firewall. Tidak ada respon diterima. Ini adalah kondisi yang diinginkan untuk port yang tidak boleh diakses publik.

❔ open|filtered
Ambigu — biasanya terjadi pada UDP scan. Nmap tidak bisa membedakan antara terbuka atau difilter karena tidak ada respon.
⏱️ Latency (ms)
Waktu respon host. <5ms = perangkat di LAN lokal. >50ms = mungkin melalui link lambat atau VPN. Berguna untuk mendeteksi perangkat "tersembunyi".
🏷️ MAC Address
Alamat hardware network interface. Prefix (3 byte pertama) menunjukkan vendor/produsen. Contoh: B8:27:EB = Raspberry Pi Foundation.
📋 Service Banner
Identifikasi service dan versinya. Contoh: OpenSSH 8.9p1 Ubuntu. Informasi ini bisa digunakan untuk mencari CVE (kerentanan) pada versi tersebut.

Analisis Output di Atas:

  • Port 22 (SSH open) → Router Xiaomi punya SSH aktif. Cek apakah SSH ini dibutuhkan. Pastikan menggunakan password kuat atau key-based auth.
  • Port 53 (DNS open) → Normal untuk router — router menjalankan DNS server (dnsmasq) untuk jaringan lokal.
  • Port 80/443 (HTTP/HTTPS open) → Panel admin router (LuCI interface). Normal, tapi pastikan tidak terekspos ke internet.
  • Port 8080 (filtered) → Diblokir firewall, tidak bisa diakses dari luar. Bagus.
  • MAC: Xiaomi → Konfirmasi ini benar adalah router Xiaomi Anda.
  • Network Distance: 1 hop → Perangkat berada satu hop dari Anda (langsung terhubung, bukan melewati router lain).
// 08 — Use Cases Legal & Aman

Use Cases Legal & Aman

🏠 Audit Jaringan Rumah

Home Network Audit
# Langkah 1: Temukan semua perangkat aktif
$ sudo nmap -sn 192.168.1.0/24
# Langkah 2: Scan service pada perangkat yang ditemukan
$ sudo nmap -sV --top-ports 50 192.168.1.0/24
# Langkah 3: Simpan hasilnya untuk dokumentasi
$ sudo nmap -sV -oN audit_rumah_$(date +%Y%m%d).txt 192.168.1.0/24

🔌 Cek Port Router

Router Port Check
# Cek port penting pada router (gateway 192.168.0.1)
$ sudo nmap -sV -p 22,23,53,80,443,8080,8443,1194,8291 192.168.0.1
# Port yang TIDAK ingin Anda lihat open di router:
# 23 = Telnet (protokol lama, tidak terenkripsi, bahaya!)
# 8291 = Winbox MikroTik (jika tidak pakai MikroTik, ini aneh)
# Port random di atas 10000 = bisa jadi backdoor

📱 Temukan Perangkat IoT

IoT Device Discovery
# Scan port yang sering digunakan IoT device
$ sudo nmap -sV -p 80,443,554,8080,8443,1883,5683,9000 192.168.1.0/24
# Port khas IoT:
# 554 = RTSP (streaming kamera IP)
# 1883 = MQTT (protokol IoT)
# 5683 = CoAP (protokol IoT)
# 8443 = HTTPS alternatif (smart home devices)
# 9000 = Banyak dipakai smart TV

📦 Inventory Perangkat Jaringan

Network Inventory
# Buat inventory lengkap: host, OS, MAC address, service
$ sudo nmap -sV -O --top-ports 20 -oX inventory.xml 192.168.1.0/24
# Output grepable untuk analisis cepat
$ sudo nmap -sn -oG - 192.168.1.0/24 | grep "Up"
# Contoh output grepable:
Host: 192.168.1.1 (_gateway) Status: Up
Host: 192.168.1.100 () Status: Up
Host: 192.168.1.105 (laptop) Status: Up

🔍 Deteksi Service Lama / Vulnerable

Old Service Detection
# Deteksi service lama yang tidak aman (Telnet, FTP tanpa TLS, dll)
$ sudo nmap -sV -p 21,23,25,110,143 192.168.1.0/24
# Port berbahaya jika ditemukan open:
# 21 = FTP (transfer file tidak terenkripsi)
# 23 = Telnet (remote access tidak terenkripsi)
# 25 = SMTP (email relay terbuka)
# 110 = POP3 (email tidak terenkripsi)
# 143 = IMAP (email tidak terenkripsi)
// 09 — NSE — Nmap Scripting Engine

NSE — Nmap Scripting Engine

NSE memungkinkan Anda menjalankan skrip Lua yang tersedia untuk automasi deteksi, audit, dan enumerasi. Terdapat lebih dari 600+ skrip bawaan di Nmap.

⚠️

Perhatian: Beberapa skrip NSE bersifat invasif dan bisa mengubah konfigurasi target atau menyebabkan crash. Selalu baca deskripsi skrip sebelum menjalankan. Hanya gunakan di jaringan/perangkat milik Anda.

Kategori Skrip NSE

Kategori Deskripsi Aman?
safe Tidak akan merusak target. Direkomendasikan untuk pemula. ✅ Ya
default Kumpulan skrip yang diaktifkan dengan -sC. Sebagian besar aman. ✅ Umumnya
discovery Mengumpulkan informasi tambahan tentang jaringan dan host. ✅ Ya
vuln Deteksi kerentanan. Bisa invasif, gunakan dengan hati-hati. ⚠️ Hati-hati
exploit Mencoba eksploitasi kerentanan. JANGAN digunakan sembarangan. ❌ Tidak
brute Brute force credential. ILEGAL jika tanpa izin. ❌ Tidak

Skrip NSE Aman untuk Pemula

NSE — Safe Scripts
# Jalankan default scripts (aman, informatif)
$ sudo nmap -sC -sV 192.168.1.1
# Cek banner service (versi software yang dipakai)
$ sudo nmap --script banner 192.168.1.100
# Cek info HTTP server (title halaman, metode yang didukung)
$ sudo nmap --script http-title,http-methods -p 80,443 192.168.1.1
# Cek konfigurasi SSL/TLS
$ sudo nmap --script ssl-enum-ciphers -p 443 192.168.1.1
# Cek apakah SSH menggunakan algoritma yang aman
$ sudo nmap --script ssh2-enum-algos -p 22 192.168.1.1
# Deteksi info SNMP (network management)
$ sudo nmap --script snmp-info -sU -p 161 192.168.1.1
# Temukan semua script dari kategori "safe"
$ sudo nmap --script "safe" 192.168.1.1

Contoh Output NSE http-title

NSE Output Example
PORT STATE SERVICE VERSION 80/tcp open http OpenWrt uhttpd | http-title: | title: OpenWrt - LuCI | http-methods: | Supported Methods: GET HEAD POST |_ Potentially risky methods: (none) 443/tcp open ssl/http OpenWrt uhttpd | ssl-enum-ciphers: | TLSv1.2: | ciphers: TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384 | least strength: A
// 10 — Etika & Risiko Penggunaan

Etika & Risiko Penggunaan

🚫

ILEGAL — JANGAN LAKUKAN: Scanning jaringan atau perangkat yang bukan milik Anda tanpa izin eksplisit adalah tindakan ilegal di Indonesia (UU ITE No. 19 Tahun 2016 Pasal 30) dan bisa dikenakan pidana penjara hingga 8 tahun dan denda hingga 800 juta rupiah.

✅ BOLEH dilakukan
  • Scan jaringan rumah milik sendiri
  • Scan lab virtual machine milik sendiri
  • Scan perangkat dengan izin tertulis pemilik
  • Scan di platform legal: HackTheBox, TryHackMe, VulnHub
  • Bug bounty program yang secara eksplisit mengizinkan scanning
❌ TIDAK BOLEH dilakukan
  • Scan jaringan tetangga / kantor tanpa izin
  • Scan server perusahaan dari luar tanpa kontrak
  • Scan infrastruktur pemerintah
  • Port scan seluruh internet (mass scan)
  • Menggunakan hasil scan untuk eksploitasi

Risiko Teknis yang Perlu Diketahui

⚡ Overload pada Perangkat Lemah
Scan agresif bisa menyebabkan printer, kamera IP, atau router murah crash/freeze. Selalu gunakan timing yang tepat (-T2 atau -T3).
🚨 IDS/IPS Alert
Jika jaringan Anda dilindungi IDS, scan bisa memicu alert. Di jaringan rumah biasanya tidak ada, tapi penting diketahui.
👁️ Log di Target
TCP Connect scan (-sT) meninggalkan jejak di log sistem target. SYN scan (-sS) lebih sedikit log, tapi tetap bisa terdeteksi.
// 11 — Best Practice — Agar Tidak Mengganggu Jaringan

Best Practice — Agar Tidak Mengganggu Jaringan

Timing Templates (-T)

Flag Nama Kecepatan Rekomendasi
-T0 Paranoid Sangat lambat Tidak diperlukan di rumah
-T1 Sneaky Sangat lambat Tidak diperlukan di rumah
-T2 Polite Lambat ✅ Untuk perangkat IoT sensitif
-T3 Normal Sedang (default) ✅ Rekomendasi umum di rumah
-T4 Aggressive Cepat ⚠️ Hanya di LAN yang stabil
-T5 Insane Sangat cepat ❌ Hindari, bisa overload
Best Practice Commands
# ✅ BAIK: Scan ringan dengan timing normal
$ sudo nmap -T3 -sn 192.168.1.0/24
# ✅ BAIK: Scan terbatas pada port yang relevan
$ sudo nmap -T3 -p 22,80,443 192.168.1.1
# ✅ BAIK: Scan lambat untuk perangkat sensitif (printer, IoT)
$ sudo nmap -T2 -sV 192.168.1.50
# ❌ HINDARI: Scan UDP seluruh port di seluruh subnet
# sudo nmap -sU 192.168.1.0/24 <-- JANGAN, sangat lambat & invasif
# ❌ HINDARI: Timing insane di jaringan rumah
# sudo nmap -T5 -p- 192.168.1.0/24 <-- JANGAN

Tips Tambahan

  • Selalu simpan hasil scan dengan -oN untuk perbandingan di masa depan.
  • Lakukan scan secara berkala (misal: bulanan) untuk deteksi perangkat baru yang tidak dikenal.
  • Jika ada perangkat tidak dikenal muncul, segera investigasi — bisa jadi perangkat tetangga yang terkoneksi ke WiFi Anda.
  • Gunakan timing -T2 atau -T3 untuk menjaga kestabilan jaringan.
  • Hindari scan saat jam sibuk penggunaan (streaming, video call) karena bisa menambah beban jaringan.

// 13 — Mini Latihan Praktik Bertahap

Mini Latihan Praktik Bertahap

1
Kenali Jaringan Rumah Anda
Beginner

Tujuan: Memahami topologi jaringan Anda dan menemukan semua perangkat aktif.

1
Jalankan ip addr (Linux) atau ipconfig (Windows) untuk mengetahui IP Anda dan subnet.
2
Catat IP gateway (router) Anda — biasanya akhiran .1 atau .254.
3
Jalankan: nmap -sn 192.168.1.0/24 (ganti dengan subnet Anda).
4
Hitung berapa perangkat yang ditemukan. Apakah sesuai yang Anda harapkan?
5
Identifikasi setiap MAC address vendor — pergi ke macvendors.com dan masukkan 3 byte pertama MAC.
6
Dokumentasikan hasilnya: nama perangkat, IP, MAC, vendor.
🎯
Sukses jika Anda bisa membuat daftar semua perangkat di jaringan dengan identitas vendor-nya.
2
Audit Router
Beginner

Tujuan: Mengetahui port apa saja yang terbuka di router Anda.

1
Jalankan: sudo nmap -sV -p 22,23,53,80,443,8080 192.168.1.1
2
Catat port mana yang open.
3
Cek: apakah port 23 (Telnet) terbuka? Jika ya, ini berbahaya — segera nonaktifkan di panel admin router.
4
Cek apakah port 80 (HTTP) dan 443 (HTTPS) terbuka — ini normal untuk panel admin.
5
jalankan: sudo nmap --script http-title -p 80 192.168.1.1 lihat nama panel admin.
🎯
Sukses jika Anda bisa mengidentifikasi semua service di router dan tidak ada Telnet yang aktif.
3
Deteksi Perangkat Tidak Dikenal
Intermediate

Tujuan: Menemukan dan mengidentifikasi perangkat yang tidak Anda kenal di jaringan.

1
Jalankan host discovery: nmap -sP 192.168.1.0/24
2
Bandingkan hasil dengan perangkat yang Anda tahu (laptop, HP, router, printer, dsb.).
3
Untuk perangkat tidak dikenal, jalankan: sudo nmap -sV -O [IP_tidak_dikenal]
4
Cek MAC vendor, OS, dan service untuk mengidentifikasi jenis perangkat.
5
Jika benar-benar tidak dikenal dan tidak ada di rumah Anda, segera blokir di router.
🎯
Sukses jika Setiap perangkat bisa Anda identifikasi atau blokir jika mencurigakan.

Audit Keamanan IoT
Intermediate

Tujuan: Memeriksa keamanan perangkat IoT di rumah (kamera, smart TV, speaker pintar).

1
Temukan IP perangkat IoT dari hasil Lab 1.
2
jalankan: sudo nmap -sV -p 80,443,554,8080,8443 [IP_IoT]
3
Jalankan skrip NSE: sudo nmap --script http-title,banner -p 80,443 [IP_IoT]
4
Cek apakah ada panel admin yang bisa diakses tanpa login.
5
Cari nama model perangkat dari banner atau HTTP title, lalu cek cve.mitre.org untuk kerentanan yang diketahui.
6
Dokumentasikan temuan dan rencanakan mitigasi (update firmware, nonaktifkan port tidak perlu).
🎯
Sukses jika Anda memiliki laporan keamanan untuk setiap perangkat IoT di rumah.

NSE Script Exploration
Intermediate

Tujuan: Familiar dengan NSE untuk audit konfigurasi SSL dan SSH.

1
Cek konfigurasi SSH router: sudo nmap --script ssh2-enum-algos -p 22 192.168.1.1
2
Lihat algoritma mana yang didukung — apakah ada yang deprecated (arcfour, 3des-cbc)?
3
Jika ada HTTPS: sudo nmap --script ssl-enum-ciphers -p 443 192.168.1.1
4
Perhatikan "least strength" — idealnya minimal grade B.
5
Coba skrip http-headers: sudo nmap --script http-headers -p 80 192.168.1.1
6
Apakah ada security header seperti X-Frame-Options, X-XSS-Protection?
🎯
Sukses jika Anda bisa membaca dan menginterpretasikan output NSE untuk evaluasi konfigurasi keamanan.
🎓

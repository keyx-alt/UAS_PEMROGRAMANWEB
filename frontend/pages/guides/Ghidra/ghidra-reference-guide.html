1.1 Apa itu Ghidra?

Ghidra adalah Software Reverse Engineering (SRE) framework open-source yang dikembangkan dan dirilis ke publik oleh NSA (National Security Agency) pada tahun 2019. Ghidra menyediakan suite lengkap untuk analisis binary — dari disassembly, decompilasi, hingga scripting otomatis — dan mampu menangani berbagai arsitektur prosesor serta format file executable.

🔬
Multi-Platform Binary
PE (Windows), ELF (Linux), Mach-O (macOS), firmware, shellcode, dan lebih dari 30 format lainnya.
🏗
Multi-Architecture
x86/x64, ARM/ARM64, MIPS, PowerPC, RISC-V, Xtensa, dan puluhan arsitektur lainnya.
⚙️
Decompiler
Decompiler terintegrasi yang menghasilkan pseudocode C dari binary — fitur yang di IDA Pro berbayar mahal.
📜
Scripting Engine
API scripting Java dan Python (Jython) untuk otomasi analisis, ekstraksi IOC, dan custom analysis.
🤝
Collaborative
Mode shared project untuk kolaborasi tim analisis secara real-time pada satu binary.
🔓
Open Source & Free
Tersedia di GitHub (github.com/NationalSecurityAgency/ghidra) di bawah Apache License 2.0.

1.3 Fungsi Utama dalam Malware Analysis

🔍 Static Analysis — Analisis tanpa eksekusi Core ▶

Ghidra memungkinkan analis untuk membedah binary secara mendalam tanpa harus mengeksekusinya — jauh lebih aman untuk malware:

  • Disassembly — Konversi machine code ke assembly yang terbaca.
  • Decompilasi — Rekonstruksi pseudocode C mendekati source code asli.
  • String extraction — Identifikasi URL, registry key, embedded config, dan hardcoded IOC.
  • Import analysis — Analisis fungsi Windows API yang di-import untuk deduksi perilaku.
  • Cross-reference (XREF) — Lacak semua caller/callee suatu fungsi atau lokasi data.
  • Control flow graph — Visualisasi jalur eksekusi program.
⚙️ Reverse Engineering — Rekonstruksi logika program Core ▶
  • Function naming & annotation — Beri nama meaningful pada fungsi yang belum dikenali.
  • Data type recovery — Rekonstruksi struct, class, dan custom data type.
  • Calling convention analysis — Identifikasi parameter dan return value fungsi.
  • Obfuscation reversal — Decode string encryption, API hashing, dan control flow flattening.
  • Config extraction — Lokasi dan decode embedded configuration malware.
🤖 Automation & Scripting Power ▶
  • Batch analysis — Proses ribuan sample secara otomatis via Ghidra Headless Analyzer.
  • IOC extraction script — Otomasi ekstraksi domain, IP, registry key dari binary.
  • Auto-renaming — Script untuk rename fungsi berdasarkan pattern yang diketahui.
  • YARA rule generation — Generate signature dari byte pattern yang ditemukan.
  • Malware family classification — Bandingkan fungsi hash antar sample untuk clustering.

1.7 Keterbatasan Ghidra

⚠️ Common Pitfalls & Keterbatasan Penting ▶
  • Startup time lambat — Ghidra berbasis Java (JVM), startup dan auto-analysis bisa memakan waktu lama untuk binary besar (>50MB).
  • Memory hungry — Default heap 768MB sering tidak cukup. Edit ghidraRun / analyzeHeadless untuk -Xmx4g.
  • False positives pada decompiler — Decompiler Ghidra kadang salah menginterpretasi code pattern, terutama pada obfuscated atau hand-crafted assembly. Selalu verifikasi dengan listing view.
  • Tidak ada debugger built-in — Ghidra tidak memiliki debugger terintegrasi (berbeda dengan IDA Pro dengan WinDbg bridge). Gunakan x64dbg/WinDbg untuk dynamic analysis terpisah.
  • Plugin ecosystem lebih kecil dari IDA — Meskipun berkembang pesat, plugin Ghidra belum setingkat IDA untuk beberapa niche task (e.g., FLIRT signature parity).
  • Collaborative memerlukan server — Fitur shared project membutuhkan setup Ghidra Server terpisah.
⚠️
Peringatan Penting

Jangan pernah membuka malware sample di host machine utama Anda. Selalu gunakan isolated VM yang di-snapshot sebelum analisis, preferably tanpa koneksi internet aktif. Ghidra sendiri aman digunakan untuk static analysis, namun binary yang dianalisis bisa saja memiliki anti-VM atau trigger melalui metode lain.

2.4 Safe Malware Lab — VM Setup

🚨
CRITICAL: Jangan Analisis Malware di Host Machine

Selalu gunakan isolated VM untuk analisis malware aktif. Static analysis di Ghidra relatif aman, namun tetap jalankan di VM sebagai best practice — terutama jika binary akan dieksekusi untuk dynamic analysis lanjutan.

🖥

Pilihan terbaik untuk lab. Snapshot support excellent. NAT network isolation mudah dikonfigurasi. Tersedia versi gratis (Player).
📦

Free & open source. Snapshot support tersedia. Sedikit lebih lambat dibanding VMware. Cocok untuk budget terbatas.
🔒

Distro Linux khusus malware analysis. Sudah pre-installed: Ghidra, FLOSS, Capa, Radare2, dll. Download: remnux.org
🛡
FlareVM
Windows-based malware analysis VM oleh FLARE team Mandiant. Script PowerShell untuk setup otomatis. Tersedia di GitHub.

Item Aksi Prioritas

2.5 Setup Ghidra Project Pertama

Setelah Ghidra terbuka, langkah pertama adalah membuat Project. Project adalah container yang menyimpan semua hasil analisis, annotation, dan script untuk satu atau lebih binary terkait.

📁 Membuat Project Baru ▶
  1. Buka Ghidra → Tampil Project Manager window.
  2. File → New Project (atau Ctrl+N).
  3. Pilih Non-Shared Project (untuk solo analysis) atau Shared Project (untuk kolaborasi tim dengan Ghidra Server).
  4. Pilih direktori penyimpanan dan beri nama project (misal: malware-2026-05-campaign).
  5. Klik Finish.
💡
Naming Convention

Beri nama project dengan format YYYY-MM-[campaign/family/ticket] agar mudah diorganisir. Satu project bisa berisi banyak binary terkait dari satu kampanye atau malware family.

🗂 Struktur File Project Ghidra ▶
tree
malware-2026-05-campaign/
├── malware-2026-05-campaign.gpr     # Project descriptor
└── malware-2026-05-campaign.rep/    # Repository folder
    ├── idata/
    │   └── 00/
    │       └── 00/
    │           └── <binary-hash>    # Ghidra database per file
    ├── user/                         # User-specific settings
    └── versioned/                    # Version history

File .gpr adalah yang dibuka saat re-open project. Seluruh data analisis (annotation, comments, renamed functions) tersimpan di .rep/ folder — backup folder ini secara rutin.

2.6 Ghidra Headless Analyzer

analyzeHeadless memungkinkan Ghidra berjalan tanpa GUI — ideal untuk batch processing ratusan sample secara otomatis dalam pipeline CI/malware-analysis.

bash
# Sintaks dasar analyzeHeadless
./support/analyzeHeadless <project_location> <project_name> \
  -import <binary_path> \
  -postScript <MyScript.java> \
  -deleteProject

# Contoh: Analisis sample.exe dan jalankan script ekstraksi string
./support/analyzeHeadless /tmp/ghidra_projects SampleAnalysis \
  -import /malware/samples/sample.exe \
  -postScript ExtractStrings.java \
  -scriptPath /home/analyst/ghidra_scripts \
  -deleteProject

# Batch import seluruh folder
./support/analyzeHeadless /tmp/ghidra_projects BatchProject \
  -import /malware/samples/ \
  -recursive \
  -postScript IOCExtractor.java \
  -deleteProject
💡
Automation Use Case

Headless mode ideal untuk integrasi dengan sandbox pipeline, MISP, atau SOAR platform. Script Python/Java dapat mengoutput JSON IOC yang langsung dikonsumsi oleh threat intel platform.

3.3 Decompiler

Panel paling krusial untuk malware analysis. Ghidra menggunakan engine decompiler berbasis P-code IR (intermediate representation) untuk menghasilkan pseudocode C yang mendekati source code asli.

Contoh Output Decompiler — Fungsi Enkripsi XOR Example ▶
c — pseudocode ghidra
/* Ghidra decompiler output — BEFORE renaming */
void FUN_00401230(char *param_1, int param_2, char param_3)
{
  int iVar1;

  iVar1 = 0;
  while (iVar1 < param_2) {
    param_1[iVar1] = param_1[iVar1] ^ param_3;
    iVar1 = iVar1 + 1;
  }
  return;
}

/* AFTER analyst renames variables + parameters */
void xor_decrypt_buffer(char *buffer, int length, char xor_key)
{
  int i;

  i = 0;
  while (i < length) {
    buffer[i] = buffer[i] ^ xor_key;  // single-byte XOR loop
    i = i + 1;
  }
  return;
}

Decompiler Ghidra kadang menghasilkan konstruksi yang tidak akurat, terutama pada: (1) hand-crafted assembly, (2) stack frame manipulation yang tidak konvensional, (3) obfuscated control flow. Selalu verifikasi pseudocode dengan raw listing untuk bagian kritis.

3.6 Memory Map

Menampilkan semua memory segments / sections dari binary yang dimuat, beserta permission dan address range-nya.

Contoh Memory Map — PE File Typical PE Analysis ▶
Section Start Size R W X Keterangan
.text 0x00401000 0x12000 ✅ ❌ ✅ Code — executable. Malware mungkin tambah section ini untuk hidden code.
.rdata 0x00413000 0x4000 ✅ ❌ ❌ Read-only data, import table, strings konstanta

⚠️
Red Flag: Section RWX

Section dengan permission Read + Write + Execute secara bersamaan adalah anomali besar. Ini sering menandakan packed binary, shellcode stub, atau area yang digunakan untuk self-modifying code / process injection.

3.7 Data Type Manager

Kelola semua struct, typedef, enum, dan union. Sangat penting untuk merekonstruksi config malware, network packet struct, atau Windows API struct yang kompleks.

Membuat Custom Struct — Contoh Config Malware Advanced ▶

Skenario: Malware memiliki embedded config struct. Kita rekonstruksi dari decompiler:

c — struct definition
/* Contoh struct config yang ditemukan dari decompiler analysis */
typedef struct _MALWARE_CONFIG {
  char    c2_host[256];      // offset 0x00: C2 domain/IP (null-terminated)
  uint16_t c2_port;          // offset 0x100: port number
  uint8_t  xor_key;          // offset 0x102: single-byte XOR key

5.2 Static Analysis Strategy

Setelah triage, mulai deep static analysis di Ghidra. Gunakan strategi top-down (dari entry point) atau bottom-up (dari suspicious API/string) tergantung kompleksitas binary.

Top-Down vs Bottom-Up Strategy Strategy ▶
⬇️
Top-Down (Entry Point First)
Mulai dari entry() atau WinMain, ikuti alur eksekusi. Cocok untuk binary kecil-sedang atau saat ingin memahami full lifecycle malware. Lebih lambat tapi komprehensif.
⬆️
Bottom-Up (API/String First)
Mulai dari suspicious API (VirtualAlloc, RegSetValue) atau string IOC, trace ke atas via XREF. Cocok untuk binary besar atau saat mencari behavior spesifik. Lebih cepat untuk targeted analysis.
💡
Rekomendasi untuk Malware Analysis

Mulai dengan Bottom-Up untuk identifikasi cepat kapabilitas utama (injection, persistence, C2). Setelah fungsi kunci ditemukan, gunakan Top-Down untuk memahami full execution flow dan initialization sequence (di mana config di-load, kapan enkripsi dimulai, dll).

# Ekstrak string-based IOC dan simpan ke file
import re, os

def extract_ioc():
    iocs = {'urls': [], 'ips': [], 'registry': [], 'mutex': [], 'paths': []}
    # Pattern untuk matching
    patterns = {
        'urls':     re.compile(r'https?://[^\s"\'<>]+'),
        'ips':      re.compile(r'\b(?:\d{1,3}\.){3}\d{1,3}\b'),
        'registry': re.compile(r'HK(?:CU|LM|CR|U|CC)\\[^\x00]+', re.IGNORECASE),
        'paths':    re.compile(r'%(?:APPDATA|TEMP|WINDIR|SYSTEM32)%\\[^\x00]+', re.IGNORECASE),
    }
    # Iterate semua defined strings di program
    mem  = currentProgram.getMemory()
    listing = currentProgram.getListing()
    data_iter = listing.getDefinedData(mem.getMinAddress(), True)

    while data_iter.hasNext():
        d = data_iter.next()
        try:
            val = str(d.getValue())
            for cat, pat in patterns.items():
                matches = pat.findall(val)
                iocs[cat].extend(matches)
        except:
            pass
    # Output ke console
    for cat, items in iocs.items():
        if items:
            print(f"\n[IOC] {cat.upper()}:")
            for item in set(items):
                print(f"  {item}")

# (ditemukan dari decompiler: key=0x5A, blob di offset 0x4020)
import pefile, struct

def xor_decode(data: bytes, key: int) -> bytes:
    return bytes(b ^ key for b in data)

pe = pefile.PE("sample.exe")
# Ambil raw data dari .data section
for section in pe.sections:
    if section.Name.startswith(b'.data'):
        raw = section.get_data()
        # Decode config blob (offset 0 dalam section, panjang 0x1A0)
        config_enc = raw[0x00:0x1A0]

/* Classic Remote DLL Injection pattern */
/* Identifikasi: 4 API ini berurutan = injection */
void inject_dll(DWORD target_pid, const char *dll_path)
{
  HANDLE hProcess, hThread;
  LPVOID remote_mem;
  size_t path_len = strlen(dll_path) + 1;

  // 1. Buka handle ke target process
  hProcess = OpenProcess(
      PROCESS_ALL_ACCESS, FALSE, target_pid); // ← API #1

  // 2. Alokasikan memori di target process untuk DLL path
  remote_mem = VirtualAllocEx(
      hProcess, NULL, path_len,               // ← API #2
      MEM_COMMIT, PAGE_READWRITE);

  // 3. Tulis DLL path ke memori target
  WriteProcessMemory(
      hProcess, remote_mem,                   // ← API #3
      dll_path, path_len, NULL);

  // 4. Buat remote thread yang memanggil LoadLibraryA
  //    → LoadLibraryA akan load DLL kita ke target process
  hThread = CreateRemoteThread(
      hProcess, NULL, 0,                      // ← API #4
      (LPTHREAD_START_ROUTINE)GetProcAddress(
          GetModuleHandle("kernel32.dll"),
          "LoadLibraryA"),               // ← target fungsi
      remote_mem, 0, NULL);

  WaitForSingleObject(hThread, INFINITE);
  CloseHandle(hThread);
  CloseHandle(hProcess);
}

from ghidra.program.model.symbol import SourceType

# Mapping: API name → prefix yang akan diberikan ke fungsi caller
API_RENAME_MAP = {
  "VirtualAllocEx":      "alloc_remote_mem",
  "WriteProcessMemory":  "write_proc_mem",
  "CreateRemoteThread":  "inject_thread",
  "RegSetValueEx":       "persist_registry",
  "InternetConnect":     "net_connect",
  "HttpSendRequest":     "net_http_send",
  "CryptUnprotectData":  "decrypt_dpapi",
  "FindFirstFile":       "enum_files",
  "SetWindowsHookEx":    "install_hook",
  "CreateService":       "install_service",
}

def get_called_apis(func):
    """Ambil semua nama fungsi yang dipanggil dalam func."""
    called = []
    body   = func.getBody()
    insn_iter = currentProgram.getListing().getInstructions(body, True)
    while insn_iter.hasNext():
        insn = insn_iter.next()
        refs = insn.getReferencesFrom()
        for ref in refs:
            sym = currentProgram.getSymbolTable().getPrimarySymbol(ref.getToAddress())
            if sym: called.append(sym.getName())
    return called

def main():
    fm       = currentProgram.getFunctionManager()
    funcs    = fm.getFunctions(True)
    renamed  = 0

    while funcs.hasNext():
        func = funcs.next()
        # Hanya proses fungsi yang belum di-rename (masih FUN_*)
        if not func.getName().startswith("FUN_"): continue

        called_apis = get_called_apis(func)
        for api, prefix in API_RENAME_MAP.items():
            if api in called_apis:
                new_name = "{}_{}x".format(prefix, func.getEntryPoint())
                try:
                    func.setName(new_name, SourceType.USER_DEFINED)
                    print("[+] Renamed: {} → {}".format(
                        func.getEntryPoint(), new_name))
                    renamed += 1
                except:
                    pass
                break  # satu rename per fungsi cukup

    print("[*] Total renamed: {}".format(renamed))

from ghidra.program.model.listing import CodeUnit

DECRYPT_FUNC_ADDR = 0x00401230  # ← ganti: address fungsi decrypt
XOR_KEY           = 0x5A         # ← ganti: XOR key dari analisis

def xor_decrypt(data, key):
    return bytes(b ^ key for b in data)

def read_bytes_until_null(addr, max_len=256):
    """Baca bytes dari Ghidra memory hingga null terminator."""
    result = []
    mem    = currentProgram.getMemory()
    for _ in range(max_len):
        try:
            b = mem.getByte(addr) & 0xFF
            if b == 0: break
            result.append(b)
            addr = addr.add(1)
        except: break
    return bytes(result)

def main():
    prog    = currentProgram
    listing = prog.getListing()
    ref_mgr = prog.getReferenceManager()

    decrypt_addr = toAddr(DECRYPT_FUNC_ADDR)
    xrefs        = ref_mgr.getReferencesTo(decrypt_addr)
    annotated    = 0

    for xref in xrefs:
        call_addr = xref.getFromAddress()
        insn      = listing.getInstructionAt(call_addr)
        if insn is None: continue

        # Cari instruksi PUSH sebelum CALL (parameter pertama = encrypted ptr)
        prev_insn = insn.getPrevious()
        if prev_insn and prev_insn.getMnemonicString() == "PUSH":
            try:
                enc_addr = toAddr(int(prev_insn.getDefaultOperandRepresentation(0), 16))
                enc_data = read_bytes_until_null(enc_addr)
                dec_str  = xor_decrypt(enc_data, XOR_KEY).decode("latin-1")

                # Tambahkan decoded string sebagai EOL comment pada CALL instruction
                listing.setComment(call_addr,
                    CodeUnit.EOL_COMMENT,
                    '[DECRYPT] "{}"'.format(dec_str))

                print("[+] {} → {}".format(call_addr, dec_str))
                annotated += 1
            except Exception as e:
                print("[-] Error at {}: {}".format(call_addr, e))

    print("[*] Annotated {} call sites.".format(annotated))

import ghidra.app.script.GhidraScript;
import ghidra.program.model.listing.*;
import ghidra.program.model.symbol.*;
import java.util.*;

public class FunctionComplexityAnalyzer extends GhidraScript {

  record FuncInfo(String name, String addr, int instCount, int xrefIn) {}

  @Override
  public void run() throws Exception {
    FunctionManager  fm      = currentProgram.getFunctionManager();
    ReferenceManager refMgr  = currentProgram.getReferenceManager();
    Listing          listing = currentProgram.getListing();
    List<FuncInfo>   results = new ArrayList<>();

    monitor.setMessage("Analyzing functions...");
    FunctionIterator it = fm.getFunctions(true);

    while (it.hasNext()) {
      if (monitor.isCancelled()) break;
      Function func = it.next();

      // Hitung instruksi dalam fungsi
      InstructionIterator insns =
          listing.getInstructions(func.getBody(), true);
      int instCnt = 0;
      while (insns.hasNext()) { insns.next(); instCnt++; }

      // Hitung XREF masuk (berapa kali fungsi ini dipanggil)
      ReferenceIterator xrefs =
          refMgr.getReferencesTo(func.getEntryPoint());
      int xrefCnt = 0;
      while (xrefs.hasNext()) { xrefs.next(); xrefCnt++; }

      results.add(new FuncInfo(func.getName(),
          func.getEntryPoint().toString(), instCnt, xrefCnt));
    }

    // Sort by XREF descending — fungsi paling banyak dipanggil = paling penting
    results.sort((a, b) -> b.xrefIn() - a.xrefIn());

    println("\n--- TOP 20 MOST-REFERENCED FUNCTIONS ---");
    results.stream().limit(20).forEach(f ->
      println(String.format("  %-40s  %s  insts:%-5d xrefs:%-4d",
          f.name(), f.addr(), f.instCount(), f.xrefIn()))
    );
  }
}

8.5 Shellcode Analysis

Shellcode adalah raw machine code tanpa PE header — tidak ada import table, tidak ada relocation. Sering di-inject ke dalam proses lain atau dieksekusi langsung dari memori.

Import Shellcode ke Ghidra Technique ▶
  1. File → Import File → pilih raw shellcode binary (misal shellcode.bin).
  2. Format: pilih "Raw Binary" (bukan PE/ELF).
  3. Language: x86:LE:32:default (32-bit) atau x86:LE:64:default (64-bit).
  4. Base address: set ke alamat aktual di mana shellcode akan di-load (misal dari dynamic analysis).
  5. Setelah import, posisikan cursor ke byte pertama → klik kanan → Disassemble (D).
  6. Klik kanan lagi → Create Function untuk mendefinisikan entry point.

next_instruction:
  POP  EBP                  ; EBP sekarang = address "next_instruction"
  SUB  EBP, 5               ; EBP = base address shellcode (delta technique)

  ; PEB walk untuk dapatkan kernel32 base
  MOV  EAX, FS:[0x30]       ; PEB
  MOV  EAX, [EAX + 0x0C]    ; PEB.Ldr
  MOV  EAX, [EAX + 0x14]    ; Ldr.InMemoryOrderModuleList.Flink
  MOV  EAX, [EAX]           ; next entry (ntdll)
  MOV  EAX, [EAX]           ; next entry (kernel32)
  MOV  EBX, [EAX + 0x10]    ; kernel32 DllBase

  ; Dari sini: walk export table kernel32 → resolve fungsi yang dibutuhkan
  PUSH 0x0097BC257          ; ← hash "VirtualAlloc"
  CALL resolve_by_hash

#include <sys/ptrace.h>

int is_traced(void) {
  return (ptrace(PTRACE_TRACEME, 0, 0, 0) == -1); // fail = already traced
}

/* Linux anti-debug: /proc/self/status TracerPid */
int check_tracer_pid(void) {
  FILE *f = fopen("/proc/self/status", "r");  // IOC: /proc/self/status
  char line[256];
  while (fgets(line, sizeof(line), f)) {
    if (strncmp(line, "TracerPid:", 10) == 0) {
      fclose(f);
      return atoi(line + 10) != 0;  // non-zero = being traced
    }
  }
  return 0;
}

Common x86 Instruction Patterns Patterns ▶
asm — common patterns quick ref
; ── Null / Zero register ─────────────────
  XOR  EAX, EAX       ; EAX = 0 (lebih efisien dari MOV EAX,0)
  SUB  EAX, EAX       ; sama efeknya

; ── Get current address (EIP) ────────────
  CALL next           ; push EIP ke stack, jump ke next
next: POP EBX         ; EBX = address "next" — shellcode delta trick

; ── Check flag + conditional jump ────────
  TEST EAX, EAX       ; set ZF jika EAX == 0
  JZ   label          ; jump if EAX == 0
  JNZ  label          ; jump if EAX != 0

  CMP  EAX, 5         ; set flags dari EAX - 5
  JE   label          ; jump if EAX == 5
  JL   label          ; jump if EAX < 5 (signed)
  JB   label          ; jump if EAX < 5 (unsigned/below)

; ── Stack frame setup ────────────────────
  PUSH EBP            ; save caller's base pointer
  MOV  EBP, ESP       ; set new base pointer
  SUB  ESP, 0x20      ; allocate 32 bytes for locals
  ...
  MOV  ESP, EBP       ; restore stack pointer
  POP  EBP            ; restore base pointer
  RET                 ; return to caller

; ── String ops ───────────────────────────
  REP MOVSB           ; copy ECX bytes from ESI to EDI
  REP STOSB           ; fill ECX bytes at EDI with AL
  REP SCASB           ; scan EDI for AL (strlen trick: REPNE SCASB)

; ── PEB access (x86) ─────────────────────
  MOV  EAX, FS:[0x30] ; PEB address (x86)
  MOV  RAX, GS:[0x60] ; PEB address (x64)

; ── PUSHAD/POPAD (packer pattern) ────────
  PUSHAD              ; save all GP registers (EAX-EDI)
  ...                 ; packer stub code
  POPAD               ; restore all GP registers
  JMP  OEP            ; jump to original entry point

9.5 Common Analyst Pitfalls

Pitfall Dampak Mitigasi
Trust decompiler 100% Kesimpulan salah pada obfuscated/hand-crafted code Selalu verifikasi decompiler output dengan raw listing untuk fungsi kritis
Analisis packed binary tanpa unpack dulu XREF salah, fungsi tidak terdeteksi, string tidak muncul Cek entropy dulu; unpack sebelum full analysis
